#+AUTHOR: Javier Castilla

* Overview

=org-scribe= is a comprehensive, batteries-included toolkit for novelists, short story writers, and creative writers working in Emacs Org-mode. It provides everything you need from project creation to final export: templates, writing environments, word counting, progress tracking, and powerful search capabilities.

* Features

** Complete Workflow

*** Project Creation & Templates
- *Create Novel Projects*: Generate complete project structure from templates with a single command
- *A Writing Method, Not Just Scaffolding*: novel templates implement a coherent method — a causal chain per character, thirteen non-negotiable plot points, and one checklist that tells you when to stop planning ([[*The writing method behind the templates][details]])
- *Scene Insertion*: Insert pre-formatted scene templates with metadata properties
- *Chapter Insertion*: Add chapter templates with word count tracking; automatically inserts a ready-to-fill first scene below the chapter heading
- *Template Customization*: Edit templates to match your workflow
- *Bilingual Support*: English and Spanish templates included, structurally identical and test-enforced
- *Project-Wide Spelling Dictionary*: a generated =.dir-locals.el= points every file in the project at the dictionary for its language, with no per-file setup and no local-variables prompt ([[*Spelling dictionary for the whole project][details]])
- *Git Integration*: Projects automatically initialized with git

*** Writing Tools
- *Character Linking*: ID-based links between scenes and character profiles
  - Automatic ID creation for captured characters
  - Click character names in scene properties to jump to full profiles
  - Menu-based character selection for scene properties
  - Searches work with both plain text and ID links
  - Stable links that survive character name changes
- *Character Relationships*: Track a simple typed list of relationships between characters
  - Directed relationships (source → target, type)
  - Interactive relationship management
  - Plain-list view per character; table view for the whole project
- *Location Linking*: ID-based links between scenes and location profiles
  - Same linking system for locations/settings
  - Jump from scene to detailed location descriptions
- *Plot Point Linking*: tag each scene with the non-negotiable plot point it serves
  - The thirteen points ship with every novel project, already linkable
  - The health report lists any point no scene serves yet — the method's own check, mechanized
  - =F8 F8 G= to tag a scene, =F8 F8 L J= to jump from a scene to its point
- *Plot Thread Linking*: ID-based links for plot threads and subplots
  - Track main plot and subplots across your novel
  - Timeline visualization showing plot distribution
  - Health reports identify plot issues (gaps, low coverage, abandoned threads)
  - Statistics showing plot thread presence across chapters
- *Column View Enhancement*: Clean property display in org-mode column view
  - Automatically strips ID link syntax in column view
  - Shows "Alex" instead of "[[id:abc123][Alex]]"
  - Works with all linked properties (PoV, Characters, Plot, Location)
- *Entity Tooltips* (opt-in): Inline character information without opening a new buffer
  - Moving point onto any =[[id:...]]= link shows Role, Age, Goal, Motivation in the echo area
  - Enabled with =(setq org-scribe-overlays-enable t)= — off by default
  - Toggle manually with =M-x org-scribe-overlays-mode= or =F8 F8 L T= (Links & upkeep → Tooltips)
- *Word Counting*: Accurate word counting that excludes Org-mode metadata (comments, properties, drawers)
- *Scene-level Word Count Update*: =org-scribe-update-scene-wordcounts= updates =:WORDCOUNT:= on every scene heading in the current subtree without touching chapter or act headings (=M-x org-scribe-update-scene-wordcounts=)
- *Writing Modes*: Four mutually exclusive modes for different workflows:
  - Distraction-free writing mode
  - Focus mode with buffer narrowing
  - Project navigation mode (with treemacs and imenu-list)
  - Three-pane editing layout
- *Search Functions*: Find scenes by POV, character, location, or plot keywords using org-ql (handles ID links)
- *Edit Marker Index*: Collects the =*EDIT*= / =*NOTE*= markers you leave inline while drafting into one navigable buffer, grouped by category, each linking back to its exact line. Markers live in Org comment blocks, so they never reach your exported manuscript and never inflate your word counts
- *Dictionary Tools*: definitions and synonyms that both work *offline* when the local data is installed — a Wikcionario served by kiwix-serve for definitions, the system thesaurus for synonyms — falling back to the online RAE and WordReference otherwise. Inflected words resolve either way, so looking up =corriendo= finds =correr=
- *Capture System*: Project-aware note capture that finds the right notes file; character/location/object/timeline/plot-thread templates are fully localized to the project's own language (English/Spanish), independent of your global UI language setting
- *Project Health Report*: =org-scribe-project-health= aggregates the Starting Gate (how many of its eight items are done, two of them measured rather than self-reported), word-count progress, scene completion by TODO state, scenes missing critical properties, orphaned characters/locations, plot points no scene serves yet, and open TODOs in a single =*org-scribe-health*= buffer with clickable links (=F8 F8 H=)
- *Export Filters*: Scene break replacement for different export backends
- *Manuscript Compilation*: =org-scribe-compile= (=F8 F8 X=) turns the working file — apparatus sections, act/chapter/scene structure, property drawers, edit markers and all — into a clean, readable document. Chapters become visible headings, scenes stay silent, breaks between them are derived from structure rather than typed. Formats: Org, plain text, Markdown, ODT need nothing beyond Emacs; PDF (via a LaTeX distribution) and DOCX (via pandoc) are available when those optional tools are installed, reported by =org-scribe-setup-check= like any other optional dependency. The intermediate =.org= file is always kept beside the output, so a compile that looks wrong is inspectable
- *Hydra Menu*: Unified keyboard-driven menu for quick access to all functions
- *Writing Planner* (bundled): Connect writing goal planning to your manuscript — auto-loads plans, pushes live word counts, shows daily progress in the mode line, and adds a planner sub-menu at =W=. Available automatically; no separate install needed.

** Bilingual Support

Full support for English/Spanish bilingual writing:
- Spanish definitions: offline via a local Wikcionario, or the RAE online
- Synonym lookup: offline via the system thesaurus, or WordReference online
- Bilingual project structure support (notes/notas directories)
- Bilingual UI: every command prompt, message, and error is available in Spanish too — set =(setq org-scribe-message-language 'es)= (default =en=)
- Bilingual capture templates: character/location/object/timeline/plot-thread capture prompts and headings automatically match *the project's own language* (read from the =# Language:= line in =.org-scribe-project=), not the global =org-scribe-message-language= setting — a Spanish novel gets Spanish capture prompts even if your own UI language is English
- One method, two languages: the =novel-en= and =novel-es= template sets are structurally identical — same headings, same properties, same order — and =M-x org-scribe-run-parity-tests= enforces it. Only heading text and prose differ. See [[file:docs/glossary.org][docs/glossary.org]] for the term-by-term mapping

*What is /not/ translated, deliberately:* entity property names (=:Role:=,
=:Type:=, =:THREAD-TYPE:=) and their values stay English in both sets, because
they are machine-facing identifiers read by the linking layer. *Scene* property
names /are/ localized (=:Trama:= vs =:Plot:=), because you see those every day in
the property drawer and in column view.

*** Optional System Packages (not Emacs packages)

Installed with your OS package manager, not =package.el=. org-scribe reads
their data files directly — there is nothing to require or configure.

| Package         | Gives you                                                | Debian/Ubuntu                    |
|-----------------+-----------------------------------------------------------+-----------------------------------|
| =mythes-es=       | Offline synonyms, replacing the WordReference web page   | =sudo apt install mythes-es=       |

** From Source

Clone the repository:

#+begin_src sh
git clone https://codeberg.org/jcastp/org-scribe ~/.emacs.d/org-scribe
#+end_src

Add to your Emacs configuration:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/.emacs.d/org-scribe")
(require 'org-scribe)

;; Optional: Enable automatically in org-mode
(add-hook 'org-mode-hook #'org-scribe-mode)

;; Optional: Set up recommended keybindings
(org-scribe-setup)
#+end_src

** Using use-package (Recommended)

A single, batteries-included block. The required packages are pulled in
automatically; the recommended package is added explicitly because it
lives on Codeberg rather than a package archive. Drop it if you prefer
the graceful fallback.

#+begin_src emacs-lisp
;; Recommended companion (Codeberg source). Omit for graceful fallback.
(use-package org-context-extended
  :vc (:url "https://codeberg.org/jcastp/org-context-extended" :rev :newest))

(use-package org-scribe
  :vc (:url "https://codeberg.org/jcastp/org-scribe"
       :branch "main"
       :rev :newest)
  :after org
  :hook (org-mode . org-scribe-mode)
  :config
  ;; Optional appearance tweaks
  (setq org-scribe-env-work-theme 'poet)
  (setq org-scribe-env-normal-theme 'ef-deuteranopia-dark)
  (setq org-scribe-stories-directory "~/writing/exercises")

  ;; The one keybinding you need — everything hangs off this menu
  (global-set-key (kbd "<f8> <f8>") 'hydra-org-scribe/body))
#+end_src

After loading, run =M-x org-scribe-setup-check= to confirm what is active.

* Quick Start

** Read the Demo Project First

Before creating anything, it is worth ten minutes to read a project that is
already filled in. Two ship with the package, in =examples/=:

- [[file:examples/demo-novel/README.org][=examples/demo-novel/=]] — /The Morning Routine/, a novel project three weeks
  and five scenes into a first draft. It implements the writing method in
  full: a crossed Starting Gate in [[file:examples/demo-novel/design.org][design.org]], the thirteen non-negotiables
  filled in, a causal chain per character, settings with an Echo and a
  Hazard, live =*EDIT*= markers, an active writing plan, and two entities
  deliberately hidden from the timelines with =:Weight: -1=.
- [[file:examples/demo-short-story/README.org][=examples/demo-short-story/=]] — /The Last Message/, the smaller
  consolidated layout.

Both are real projects, not screenshots. Open =examples/demo-novel/novel.org=
in Emacs with org-scribe loaded and every command works against it: =<f8>
<f8> H= for the health report, =6= for the edit index, =5= for the unwritten
scenes, =C-c C-x C-c= for column view. Nothing needs installing and nothing
you do there touches your own work.

The novel demo is also deliberately imperfect — a gate box left unticked
against thirteen written plot points, two continuity errors about the same
object, an orphaned character — so that you can see what the tools say when
they find something.

** Create Your First Novel Project

1. Install the package and dependencies
2. Run =M-x org-scribe-create-novel-project=
3. Choose a directory and enter your novel title
4. Start writing in the generated =novel.org= file!

** Working in an Existing Project

1. Open an org-mode file in your project
2. Press =<f8> <f8>= to open the hydra menu
3. Try a writing workspace: press =m= for the distraction-free "write" workspace
4. Use =w= to count words in the current section
5. Insert scenes with =s= or chapters with =c=

Linking is automatic: characters, locations, and plot threads created in
your project already carry stable IDs, and tagging a scene (=p= PoV, =h=
characters, =l= locations, =g= plot threads) writes proper ID links for
you. You never need to "set up" linking by hand — the one-shot
=R= (relink project) under =L= is only there for tidying after bulk edits.

* Usage

** Project Creation

*** Create a New Novel Project

=M-x org-scribe-create-novel-project=

This creates a complete project structure:

#+begin_example
MyNovel/
├── README.org             # Project overview and navigation
├── .dir-locals.el         # Spelling dictionary for the whole project
├── design.org             # ← START HERE: Starting Gate and the Core
├── novel.org              # Main manuscript with progress tracking
├── revision.org           # The ten revision passes
├── writing-journal.org    # Reflective writing journal
├── objects/               # Planning documents
│   ├── characters.org     # Character profiles (full profile per role)
│   ├── plot.org           # The thirteen non-negotiables + narrative lines
│   ├── locations.org      # Settings, each with Echo and Hazard
│   ├── worldbuilding.org  # The world and how it presses on the Weakness
│   ├── timeline.org
│   └── objects.org
└── notes/                 # Research and notes
    ├── notes.org
    └── research.org
#+end_example

Spanish projects have the same structure with localized file names
(=diseno.org=, =novela.org=, =objects/personajes.org=, and so on).

*Open =design.org= first.* It holds the /Starting Gate/ — the one checklist that
decides when you stop planning and start writing — and the twelve questions of
the Core. Everything else is filled in as you need it.

The project includes:
- Pre-configured word count tracking
- Scene and chapter templates, with the method's scene metadata
- Progress tracking tables
- Git repository initialization

*** The writing method behind the templates

The novel templates implement a specific method rather than generic
scaffolding. Characters are built on a causal chain (Ghost → Lie →
Weakness → Desire/Need); plot is built on thirteen non-negotiable points;
scenes are checked for a /Gap/ between what the character expected and what the
world gave them.

You do not have to adopt it. The templates are ordinary Org files: delete what
you do not use, and org-scribe's linking, search and reporting keep working, as
they key off properties (=:Role:=, =:Type:=, =:THREAD-TYPE:=) rather than off
the method's headings.

The English and Spanish template sets are two renderings of *one* method, and a
test enforces that they stay structurally identical. The Spanish↔English
vocabulary — and the reasoning behind each choice — is in [[file:docs/glossary.org][docs/glossary.org]].

*Projects created before this change keep the structure they were created with.*
Templates are read once, at project creation, and copied; nothing re-reads them
afterwards. There is no migration to run and none is planned — the linking
layer handles both structures.

*Short story projects still use the previous structure.* Adapting the method to
short-story scale needs editorial decisions the method does not yet make (how
many Stances at that length, which of the thirteen survive, whether subplots
exist at all), so it is deliberately deferred rather than guessed at.

*** Spelling dictionary for the whole project

A project is monolingual by construction: the language you pick at creation is
recorded in =.org-scribe-project= and selects the whole template set. The
spelling dictionary follows from it, so project creation writes one
=.dir-locals.el= at the project root:

#+begin_src elisp
;;; Directory Local Variables            -*- no-byte-compile: t -*-
;;; Written by org-scribe.  Language: es (see .org-scribe-project).
;;; Regenerate with M-x org-scribe-update-dir-locals.

((nil . ((ispell-local-dictionary . "es_ES")
         (jinx-languages . "es_ES"))))
#+end_src

The language is named twice because the two spell checkers in common use read
different variables and neither falls back to the other: =ispell-local-dictionary=
for ispell and flyspell, =jinx-languages= for [[https://github.com/minad/jinx][jinx]]. If you use jinx, that second
line is also what gives you the right *word completion*: a =cape-dict= word list
keyed on =jinx-languages= follows the project automatically. One value serves
both, since the codes coincide — they resolve against the same hunspell data.

Every file in the project gets the right dictionary, including the notes, the
journal, the plan, and anything you or =org-scribe-capture= create later —
none of which would ever grow a per-file =Local Variables= block. Both
variables are declared-safe locals, so the file applies silently; Emacs never
asks you to approve it. (org-scribe declares =jinx-languages= safe itself, so
the project stays silent on machines where jinx is not installed.)

Templates also ship a =#+LANGUAGE:= keyword in every file, which jinx reads
natively. That is the fallback for a file opened *outside* its project tree,
where no directory-local applies — a chapter mailed to a reader, a notes file
copied elsewhere. Inside the project the =.dir-locals.el= wins, which is the
right way round: the project is authoritative, and deleting a keyword line
costs you nothing.

To use a regional variant, set the mapping before creating projects:

#+begin_src elisp
(setq org-scribe-ispell-dictionaries '((en . "en_GB") (es . "es_MX")))
#+end_src

Set =org-scribe-write-dir-locals= to nil if you manage directory-local
variables yourself; nothing else in org-scribe reads the file.

- =M-x org-scribe-update-dir-locals= (=F8 F8 L D=) creates or refreshes the
  file for the current project, reading the language from
  =.org-scribe-project=. Use it on projects created before org-scribe
  generated the file, or after changing the mapping above. An existing file is
  only replaced after confirmation. The project health report flags a missing
  or mismatched dictionary in its Overview.
- A per-file =Local Variables= block still wins over the project-wide setting,
  so a research file quoting sources in another language can keep its own.
- If you use =guess-language=, it overrides both, per paragraph, by design.
- Spell-checking *inside* an =org-capture= buffer does not see the dictionary:
  capture works in an indirect buffer, which does not pick up directory-local
  variables. This was equally true of the per-file blocks it replaces.

** Writing Modes

*** Distraction-Free Mode (=org-scribe-writing-env-mode=)

Press =F8 F8 m= or use the hydra menu.

Changes:
- Switches to writing theme
- Changes font to writing preset
- Activates writeroom-mode
- Shows line numbers

*** Focus Mode (=org-scribe-writing-env-mode-focus=)

Press =F8 F8 f= or use the hydra menu.

Like distraction-free mode, but also narrows to the current org section.

*** Project Navigation Mode (=org-scribe-project-mode=)

Opens treemacs (file tree) and imenu-list (document outline) for easy navigation.

*** Editing Mode (=org-scribe-editing-mode=)

Three-pane layout:
- Left: Document outline (imenu-list)
- Center: Main document
- Right: The project notes file (=notes/notes.org=), the same file captures write to

Set =org-scribe-editing-right-panel= to show something else in the right pane: =revision= for the project's =revision.org=, a project-relative path string, or a function receiving the manuscript file name and returning the file to display.

** Word Counting

*** Count Words in Selection or Buffer

=M-x org-scribe-wordcount= or press =F8 F8 w= in hydra

With no prefix: reports the word count for the active region, or for the whole
buffer.  With =C-u=: runs the full heading update (same as =F8 F8 a=).

*** Update All Word Count Properties

=M-x org-scribe-ews-org-count-words= or press =F8 F8 a= in hydra

Refreshes the =WORDCOUNT= property on every heading in the buffer and, when the
writing planner is active, silently syncs today's word delta to =plan.org=.

*** Update Scene Word Counts (current subtree)

=M-x org-scribe-update-scene-wordcounts=

Updates =:WORDCOUNT:= on every scene heading (level 3, =:ignore:= tagged) in the
current subtree.  When point is on a chapter or act heading, only that
chapter/act is updated; when point is not on a heading the entire buffer is
processed.  Chapter and act headings are not touched.  Requires
=org-context-extended=.

*** Automatic Update on Save

Set =org-scribe-auto-wordcount= to =t= to trigger the full word count update
automatically every time you save the manuscript file:

#+begin_src emacs-lisp
(setq org-scribe-auto-wordcount t)
#+end_src

When enabled, saving =novel.org= (or =novela.org=) silently calls
=org-scribe-ews-org-count-words= and, if the planner is active, pushes the new
total to =plan.org= in the same operation.  Requires =org-context-extended=
(skipped silently when that package is absent).  Disabled by default to keep
saves fast and side-effect-free.

*** Generate Word Count Table with Progress

Add this to your org file:

#+begin_example
#+BEGIN: org-generate-wordcount-table
#+END:
#+end_example

Update with =C-c C-c= on the #+BEGIN line.

This generates a comprehensive table showing:
- Hierarchical heading structure (Acts, Chapters, Scenes)
- Wordcount (from =WORDCOUNT= property)
- Objective (from =WORD-OBJECTIVE= property, when set)
- Progress (auto-calculated percentage)

**Example output:**

#+begin_example
| Heading                     | Wordcount | Objective | Progress |
|-----------------------------+-----------+-----------+----------|
| - Act I                     |       711 |      5000 |      14% |
| -- Chapter 1                |       447 |      1500 |      30% |
| --- Scene 1 - The Alarm     |       167 |       500 |      33% |
| --- Scene 2 - Coffee Shop   |       280 |       500 |      56% |
#+end_example

*** Set Word Objectives for Progress Tracking

Add the =WORD-OBJECTIVE= property to your Acts, Chapters, or Scenes to enable automatic progress calculation:

#+begin_example
 * Act I :ignore:
:PROPERTIES:
:WORDCOUNT: 711
:WORD-OBJECTIVE: 5000
:END:
#+end_example

When you update the word count table (with =C-c C-c= on the #+BEGIN line), progress percentages will be automatically calculated for any section that has a =WORD-OBJECTIVE= property.

** Character Linking

*** Overview

Scene properties link character names directly to their full profiles in
=objects/characters.org=. Click a character name in a scene to jump to its
detailed profile.

This works *automatically* — you do not opt into or maintain a "linking
system." When you create a project, every character the templates ship
with already carries a stable ID; characters you add later via capture get
one too; and tagging a scene writes the ID links for you. The words "ID"
and "setup" below are implementation detail you can ignore in day-to-day
writing.

*** Tagging a Scene (the everyday flow)

From the main menu (=F8 F8=), with point on a scene heading:

- =p= — *set PoV character*: pick one character; the =:PoV:= property gets
  an ID link.
- =h= — *set characters*: pick several characters; the =:Characters:=
  property gets ID links.
- =j= — *jump to PoV character*: open the PoV character's profile. Press
  =C-c &= to jump back to the scene.

That is all most writers ever need. There is no separate "link" step.

*** Retrofitting an Existing Manuscript

If you wrote scenes with plain character names (not via the tagging
commands above), one command upgrades the whole project in a single pass:

- =F8 F8 L R= (=M-x org-scribe-relink-project=) — mints any missing IDs,
  converts plain names to ID links, and refreshes display names across
  *every* entity type (characters, locations, plot threads) at once.

The older per-type =setup= commands (=org-scribe-setup-character-links=
etc.) still exist under the =L= (Links & upkeep) menu, but =relink-project=
supersedes them for everyday use.

*Click Any Character Link*:
- Position cursor on character name in properties
- Press =C-c C-o= (or click with mouse)
- Jumps to character profile

*** How It Works

Scene properties change from plain text to ID links:

Before:
#+begin_example
:PoV: Alex
:Characters: Alex, Sam
#+end_example

After:
#+begin_example
:PoV: [[id:char-alex-rivera-001][Alex]]
:Characters: [[id:char-alex-rivera-001][Alex]], [[id:char-sam-chen-002][Sam]]
#+end_example

Benefits:
- Click to navigate to character profiles
- Links survive character renames
- Searches still work (automatic extraction)
- Quick reference while writing

*** Updating Link Display Names

** Character Timeline

*** Overview

Track character appearances across your novel using a visual timeline. See at a glance which characters appear in which scenes, who has the PoV, and identify coverage gaps.

*** Quick Start

Character timeline uses the existing character properties you're already setting:

1. Tag scenes with character information (using ID links or plain text):
   #+begin_example
   :PoV: [[id:char-alice-001][Alice]]
   :Characters: [[id:char-alice-001][Alice]], [[id:char-bob-002][Bob]]
   #+end_example

2. Add timeline block to your =novel.org= (already in template):
   #+begin_example
   #+BEGIN: character-timeline
   #+END:
   #+end_example

3. Press =C-c C-c= on the #+BEGIN line to generate/update

*** Reading the Timeline

**Symbols**:
- ◆ = Character is the Point of View character (implies presence)
- ● = Character is present in the scene (not PoV)
- (blank) = Character is not present

**Example**:
#+begin_example
| Scene              | Chapter   | Alice | Bob | Charlie |
|--------------------+-----------+-------+-----+---------|
| Scene 1 - Opening  | Chapter 1 | ◆     | ●   |         |
| Scene 2 - Meeting  | Chapter 1 | ●     |     | ●       |
| Scene 3 - Conflict | Chapter 2 | ◆     | ●   | ●       |
#+end_example

**Interpretation**:
- Alice: PoV in scenes 1 and 3, present (not PoV) in scene 2
- Bob: Present in scenes 1 and 3, absent from scene 2
- Charlie: Appears in scenes 2 and 3, absent from scene 1

*** Use Cases

1. **Character Coverage**: "Is my protagonist appearing enough?"
   - Check main character appears in 80-100% of scenes
   - Identify extended absences

2. **PoV Balance** (Multi-POV Novels): "Am I favoring one viewpoint too much?"
   - Scan ◆ symbols across characters
   - Ensure balanced distribution
   - Verify alternating pattern (if desired)

3. **Gap Detection**: "Did I forget about this character?"
   - Spot large gaps (>10 scenes without appearance)
   - Identify forgotten supporting characters
   - Plan reintroduction scenes

4. **Change Milestone Tracking**: "Is the character's change well-distributed?"
   - See all scenes featuring a specific character
   - Check that each Change Milestone's plot point actually has a scene
   - Verify the character appears at the moments their arc turns on

5. **Relationship Tracking**: "When do these characters interact?"
   - Find rows where both characters have symbols
   - Frequency of joint appearances
   - Last interaction

*** How It Works

The timeline automatically:
- Extracts character names from `:PoV:` and `:Characters:` properties
- Handles both plain text and ID links (extracts display text)
- Shows only characters who appear in at least one scene
- Sorts characters alphabetically for easy location
- Distinguishes PoV from other appearances

If a character is PoV and also in Characters property, only ◆ is shown (PoV implies presence).

*** Best Practices

1. **Consistent Tagging**: Always set both PoV and Characters properties for complete tracking

2. **Main vs. Supporting**:
   - Main characters: Should appear in 60-100% of scenes
   - Supporting characters: 20-50% coverage is normal
   - Minor characters: <20% is fine

3. **Update Regularly**:
   - After writing each chapter
   - Before planning next chapter (identify gaps)
   - During revision (overall balance check)

4. **PoV Distribution** (Multi-POV):
   - Aim for minimum scenes per PoV character per act
   - Check PoV distribution is intentional
   - Avoid accidental PoV dominance

5. **Balance with Plot Timeline**:
   - Character timeline shows *who*
   - Plot timeline shows *what*
   - Use both for complete picture

*** Example Workflow

**Scenario**: Revising Act II, checking supporting character "Eve"

1. Open =novel.org= in Progress Tracking section
2. Find Character Timeline table
3. Press =C-c C-c= to update
4. Scan Eve column:
   #+begin_example
   | Scene 5  | Ch 3 |   |   | ● |   |
   | Scene 6  | Ch 3 |   |   |   |   |  ← Gap starts
   | Scene 7  | Ch 4 |   |   |   |   |
   | Scene 8  | Ch 4 |   |   | ● |   |  ← Gap ends (3 scenes)
   #+end_example
5. Notice: Eve has a 3-scene gap (scenes 6-7)
6. Decision: Add Eve to Scene 7 for continuity
7. Update Scene 7 properties:
   #+begin_example
   :Characters: Alice, Bob, Eve
   #+end_example
8. Re-generate timeline to verify

**Result**: Eve's gap reduced, better presence continuity

** Entity Tooltips (opt-in)

*** Overview

When =org-scribe-overlays-mode= is active, moving point onto any =[[id:...][Name]]= link
inside a scene property displays a one-line tooltip in the echo area showing

For other entity types (location, plot thread) it shows the heading name.

=org-scribe-mode= is active, add the following to your init file:

#+begin_src emacs-lisp
(setq org-scribe-overlays-enable t)
#+end_src

You can also toggle tooltips manually at any time:
- =M-x org-scribe-overlays-mode= — toggle in the current buffer
- =F8 F8 L T= — toggle via the Links & upkeep submenu

*** What the Tooltip Shows

#+begin_example
[Alice Rivera]  Role: Protagonist  |  Age: 28  |  Goal: Recover the manuscript  |  Motivation: Redemption
#+end_example

The tooltip is drawn from properties in the character heading:
| Property     | Shown as        |
|--------------+-----------------|
| =:Role:=       | =Role: ...=       |
| =:Age:=        | =Age: ...=        |
| =:Goal:=       | =Goal: ...=       |
| =:Motivation:= | =Motivation: ...= |

Properties that are empty or not set are simply omitted.

*** Debounce Behaviour

The lookup is debounced: moving along a line inside the same link does not
trigger repeated file reads.  A new tooltip only appears when point moves onto
a /different/ ID.

** Search Functions

All search functions are available via the hydra menu (=F8 F8=):

- =1=: Find scenes by POV character
- =2=: Find scenes with character
- =3=: Find scenes by plot keyword
- =4=: Find scenes by location
- =5=: Find all TODO items in project
- =6=: Find all edit/note markers in project (see [[*Inline Edit Markers][Inline Edit Markers]])

Searches =1= through =5= use org properties and work with both plain text and ID links:

#+begin_example
 * Chapter 1
:PROPERTIES:
:PoV: [[id:char-alice-001][Alice]]
:Characters: [[id:char-alice-001][Alice]], [[id:char-bob-002][Bob]]
:Location: Coffee Shop
:Plot: First meeting
:END:
#+end_example

Searching for "Alice" finds this scene even with ID links!

*** Inline Edit Markers

Search =6= is different from the others: it indexes notes you leave *inside* the manuscript, attached to the sentence that needs work, rather than querying properties.

The convention is to write them inside an Org comment block:

#+begin_example
The carriage arrived before dawn, and nobody was awake to meet it.

,#+begin_comment
*EDIT*: prose - too flat. The arrival should feel ominous.
,#+end_comment
#+end_example

| Marker   | Use for                                              |
|----------+------------------------------------------------------|
| =*EDIT*= | Something to change in prose that already exists     |
| =*NOTE*= | Something to remember or check; not a change as such |

Delete the comment block once you have dealt with it — that is how a marker is "closed"; there is no separate done state.

An =*EDIT*= carries a category before a =" - "= separator. =M-x org-scribe-search-edits= (=F8 F8= then =6=) collects every marker in the project and groups them:

#+begin_example
,* Edits
,** plot
,*** [[file:novel.org::412][Scene 12]] — novel.org
    Alice's motive here contradicts chapter 1
,** character
,*** [[file:novel.org::980][Scene 30]] — novel.org
    too much interiority, cut by half
,** prose
,** scene
,** other

,* Notes
,** [[file:novel.org::455][Scene 14]] — novel.org
   check whether Alice already knows about the letter
#+end_example

Each entry links back to the exact line. In the index buffer, =g= refreshes and =q= buries it.

Categories come from =org-scribe-edit-categories= (default: plot, scene, character, prose, design). A marker whose category is missing, empty or unrecognized is grouped under =other= rather than dropped — a typo moves a marker, it never hides one. Set =org-scribe-edits-index-show-empty-categories= to =nil= if you would rather not see categories with nothing in them.

The index is built by walking Org's parse tree for comment blocks, so prose that merely mentions =*NOTE*= cannot produce a false positive. If your markers *don't* follow the comment-block convention, call it with a prefix argument (=C-u=) for =org-scribe-search-edits-rgrep=, the plain-text search that finds them anywhere.

**Typing markers.** They are plain text, so you can type them by hand. If you use [[https://github.com/minad/tempel][Tempel]], org-scribe bundles =edit= and =note= snippets:

#+begin_src elisp
(with-eval-after-load 'tempel
  (org-scribe-tempel-setup))
#+end_src

Then type =edit= or =note= in an org buffer and expand. The =edit= snippet prompts for the category from =org-scribe-edit-categories= — the same variable the index groups by, so the prompt and the grouping can never drift apart.

=org-scribe-tempel-setup= only *adds* to =tempel-path=; your own templates file is never read, modified or overridden. If you already define snippets of the same name, whichever file comes first in =tempel-path= wins. Tempel is entirely optional.

**Why the comment block matters.** It is not decoration; it buys two guarantees:

1. *Markers never reach your readers.* Org excludes comment blocks from every export backend. A marker written as bare text in a paragraph is ordinary prose and *will* appear in your exported manuscript, with nothing to warn you.
2. *Markers never inflate your word count.* Comment blocks are excluded when counting, so =:WORDCOUNT:=, progress tables and the planner's daily ledger report real prose no matter how heavily you annotate.

The word-count guarantee depends on the optional =org-context-extended= package; without it, org-scribe falls back to a plain count that counts everything, markers included. The export guarantee is pure Org behavior and always holds.

Both searches are deliberately project-wide, so markers in the manuscript, the notes file and research notes all surface in one pass. =org-scribe-edit-string= customizes what the plain-text fallback matches.

See lesson 14 of the manual for the full revision workflow, including the related =*SUMMARY*= marker for scenes you have planned but not yet written.

** Dictionary Tools

*** Definitions

=M-x org-scribe-dictionary-lookup= or press =F8 F8 d= in hydra

Looks up a Spanish word, from one of two sources.

**** Offline

Requires =kiwix-tools= and a Wikcionario ZIM, plus a =kiwix-serve= running —
see [[file:INSTALL.org][INSTALL.org]] for the download and the systemd user unit. *org-scribe never
starts or manages that server*; it checks whether it answers and says so when
it does not.

With it running, definitions arrive instantly and offline, with etymology,
numbered senses, usage examples, and per-sense synonyms and antonyms.
Inflected words resolve to their dictionary form: looking up =corriendo=
opens =correr= and says that it did. (Wikcionario does store an article for
every inflected form, but they are stubs whose whole content is a pointer to
the lemma — so following the pointer is the useful behaviour.)

Availability is probed once per session and then cached, so lookups cost no
latency. If you start =kiwix-serve= after Emacs, press =C-u= before the
lookup to force a re-probe.

**** Online (fallback)

With no local server, the Real Academia Española is queried through
=rae-api.com=, exactly as before. =M-x org-scribe-rae-api-lookup= still calls
it directly if you want the RAE specifically.

Note there is no free offline copy of the RAE's own dictionary — it is
copyrighted, which is why the offline path uses Wikcionario.

**** Choosing explicitly

#+begin_src emacs-lisp
;; 'auto (default) — local server when it answers, online RAE otherwise
;; 'wikcionario    — local only; never queries the network
;; 'rae-api        — always the online RAE
(setq org-scribe-dictionary-backend 'auto)

(setq org-scribe-wikcionario-url "http://localhost:8080")
#+end_src

A word the local server simply lacks is reported as missing, with
suggestions, rather than silently going online — otherwise a gap in your
local data would be indistinguishable from a normal network lookup.

*** Synonyms

=M-x org-scribe-sinonimo= or press =F8 F8 y= in hydra

Opens synonyms in a side window, from one of two sources.

**** Offline (recommended)

Install the system thesaurus once:

#+begin_src sh
sudo apt install mythes-es      # Debian/Ubuntu; see INSTALL.org for other distros
#+end_src

That is the whole setup — org-scribe finds =/usr/share/mythes/= on its own.
Lookups become instant, work with no network, and produce an Org buffer you
can yank straight into the manuscript, with senses grouped:

#+begin_example
#+TITLE: Synonyms: abandonar

,* Sense 1 /prnl./
abandonarse, dejarse llevar, confiarse, darse, entregarse

,* Sense 2 /tr./
desistir, renunciar, marcharse, desasistir, dejar, ceder, descuidar

,* Sense 3
aparcar, posponer, retrasar, atrasar, arrinconar, diferir, apartar
#+end_example

Add =hunspell= (=sudo apt install hunspell-es=) and inflected words resolve
too: looking up =corriendo= finds the entry for =correr= and tells you it did
so. Without it, only the exact word you typed is looked up.

**** Online (fallback)

With no thesaurus data installed, or for a word that has no local entry,
the WordReference page opens in the side window as before. You are never
left without an answer.

**** Choosing explicitly

#+begin_src emacs-lisp
;; 'auto (default) — offline when available, online otherwise
;; 'mythes        — offline only, never touch the network
;; 'wordreference — always use WordReference
(setq org-scribe-thesaurus-backend 'auto)

;; Only if your thesaurus data lives somewhere unusual
(setq org-scribe-mythes-directory "/usr/share/mythes/")
(setq org-scribe-mythes-language "es_ES")   ; es_MX, en_US, ...
#+end_src

you would actually hand to a reader. The working file is a workspace, not a
manuscript — apparatus sections, an eighteen-field property drawer per scene,
act and chapter and scene headings all marked =:ignore:=, edit markers in
comment blocks — and exporting it directly produces a wall of prose with no
chapter divisions at all, because =:ignore:= sits on chapters exactly as it
does on scenes. Compile fixes this by *transforming* the manuscript before
handing it to Org's exporters, rather than patching the exported result:

- Acts are dropped (a planning structure, not a reading one); chapter
  headings survive as real, visible headings; scene headings go silent.
- A break is inserted between consecutive sibling scenes automatically —
  derived from the document's structure, so there is nothing to remember to
  type between scenes.
- Property drawers, planning apparatus, dynamic blocks, and =*EDIT*=/=*NOTE*=
  markers are all removed, not merely excluded from export.

#+begin_example
M-x org-scribe-compile
Compile style:  clean / shunn
Compile the manuscript to:  org / txt / md / odt / pdf / docx / epub
#+end_example

Output goes to =org-scribe-compile-output-directory= (default =export/=,
relative to the project root — worth adding to =.gitignore=) as e.g.
=novel-clean.odt=, alongside the intermediate =novel-clean.org= that produced
it. That intermediate is always written, whichever format you choose: when a
compile looks wrong, open it and see whether the problem is the transform or
the renderer.

The break between scenes is configurable:

#+begin_example
(setq org-scribe-compile-scene-break "⁂")   ; the default: U+2042 ASTERISM
#+end_example

=M-x customize-group RET org-scribe RET= offers named presets (asterism,
three dots, em dash, section sign, fleuron) alongside free text. A marker
beginning with =*= or =#= is refused rather than emitted — the first is
reparsed by Org as a heading (silently splitting the manuscript) and the
second as a comment (vanishing with nothing to show it was ever there). PDF
output always shows three centered asterisks instead, regardless of this
setting: pdflatex's default fonts don't cover the asterism (or the fleuron
preset) at all — the glyph simply doesn't appear in the PDF, with no error —
and there's no reliable way to test an arbitrary glyph's font coverage from
Emacs.

**** EPUB

=epub= needs the optional =ox-epub= package (MELPA:
=M-x package-install RET ox-epub RET= — not bundled with Org, unlike every
other format here). Unlike PDF, EPUB has no font-coverage problem — it's
Unicode all the way down — so your configured scene-break marker renders
as-is. It does get its own CSS class (=org-scribe-scene-break=, styled by a
small shipped stylesheet) instead of a plain centered paragraph, so a scene
break reads as a deliberate break rather than an ordinary centered line — a
writer's own center block (an epigraph, a few lines of verse) is untouched
and keeps its plain styling. Not offered for =shunn=: EPUB is reflowable,
and standard manuscript format is a fixed-page standard.

**** Submission format (=shunn=)

The =shunn= style additionally produces a submission-ready ("standard
manuscript format") document: a contact block, word count rounded to the
nearest hundred, a centered title and byline, and — for PDF — 1-inch
margins, double spacing, and a running header reading "Surname / KEYWORD /
page" from page 2 on. It needs your author identity configured first:

#+begin_example
(setq org-scribe-author-name "Jane Alcott Doe")
(setq org-scribe-author-address '("123 Elm Street" "Springfield, IL 62704"))
(setq org-scribe-author-email "jane@example.com")
(setq org-scribe-author-phone "555-0100")           ; all optional except author-name
(setq org-scribe-author-agent '("Pat Agent" "Agent House Literary"))  ; replaces your own contact block, if set
#+end_example

=shunn= is refused, naming what's missing, without =org-scribe-author-name=
set — a manuscript with a blank contact block would be worse than an
explicit error. Two project-level =.org-scribe-project= markers customize
per-project details the same way =Plan=/=Planner= already do:

#+begin_example
# Pen-name: J.A. Doe          (byline, when it differs from your legal name)
# Running-header: TIDE        (defaults to the title's first word, uppercased)
#+end_example

Available for =org=, =txt=, =pdf= and =docx= — not =md= (no layout for a
submission standard to apply to), =odt= (no styles file yet), or =epub=
(reflowable, while Shunn is a fixed-page standard). DOCX gets
the same front-matter content as the others but no page-level formatting
(no forced double-spacing or margins): that needs a reference document
pandoc doesn't have one to fall back on, the same reasoning that keeps
=org-scribe-scene-break-replacements='s =odt= entry from hardcoding a style
name that might not exist. The PDF running header and spacing come from
=org-scribe-compile-shunn-latex-preamble= (stock LaTeX packages only —
=geometry=, =setspace=, =fancyhdr=), which you can override for different
margins or header wording.

*** Direct export with scene breaks (=C-c C-e=)

For LaTeX/PDF, EPUB, or fine-grained control over Org's own export options,
export the working file directly with Org's dispatcher (=C-c C-e=). Add this
macro to your org file:

#+begin_example
#+MACRO: scene-break SCENE-BREAK
#+end_example

Use ={{{scene-break}}}= where you want scene breaks. When exporting, scene
breaks will be replaced with appropriate separators for each backend (HTML,
LaTeX, Markdown, etc.). Note this path still needs the optional =ox-extra=
package for the manuscript's =:ignore:= tags to drop chapter/scene titles
while keeping their prose — see [[file:manual/getting-started-11-exporting.org][Lesson 11]] for the full walkthrough.

* Writing Planner

** Overview

org-scribe includes a full writing planner in =planning/org-scribe-planner.el=. It is *bundled and available automatically* — no separate install, no init.el glue required. All planner commands carry autoload cookies, so they load on first use with zero startup cost when unused.

If you previously installed [[https://codeberg.org/jcastp/org-scribe-planner][org-scribe-planner]] as a standalone package and loaded =(require 'org-scribe-planner-integration)= in your init file, remove that snippet — the compatibility shim has been deleted and the integration is built directly into the planner module.

** Opt-in Gate

A project only sees the planner after explicitly opting in — no prompts, no mode-line indicator, no health-report section, and no =plan.org= template artifact until then. The decision is recorded as a =# Planner: yes= / =# Planner: no= line in =.org-scribe-project=:

- Declining the "Create a writing plan?" prompt on project creation writes =no= — the project is never asked again.
- Accepting that prompt, or creating/loading a plan manually via =M-x org-scribe-plan=, writes =yes=.
- =M-x org-scribe-planner-enable-for-project= / =M-x org-scribe-planner-disable-for-project= (hydra =F8 F8 W E= / =X=) flip the marker directly at any time.
- An *undecided* project (no =# Planner:= line yet) behaves exactly as before this gate existed — only an explicit decline turns features off.

** What It Does

*** 1. Auto-load the Plan on Project Open

When you enter an org-scribe project whose gate is =yes=, the planner silently looks for a matching plan file and loads it. Search order:

0. Path recorded in =.org-scribe-project= (written automatically after the first load — fastest)
1. =<project-root>/plan.org=
2. =<project-root>/<title>-plan.org= (title read from =.org-scribe-project=)
3. Any =.org= file in the project root that contains a =TOTAL_WORDS= property

*** 2. Live Word Count Bridge

- =org-scribe-planner-update-progress= reads totals directly from =WORDCOUNT= properties in the manuscript — no manual prompt.
- After running =org-scribe-ews-org-count-words= (=F8 F8 a=), the active plan is updated and saved silently.

*** 3. Automatic Update on Every Save

Set =org-scribe-auto-wordcount= to =t= in your init file to have the manuscript word counts and the plan sync automatically each time you save:

#+begin_src emacs-lisp
(setq org-scribe-auto-wordcount t)
#+end_src

When enabled, saving =novel.org= (or =novela.org=) silently calls
=org-scribe-ews-org-count-words= — refreshing every heading's =WORDCOUNT= and
pushing the new total to the active plan in one step.  Requires
=org-context-extended=.  Disabled by default to keep saves fast.

*** 4. Project-Aware Commands

Inside an org-scribe project, planner commands require no file-path decisions:

- =org-scribe-planner-new-plan= pre-fills the project title and saves to =<root>/plan.org= automatically — no title prompt, no save-path picker.
- =org-scribe-planner-load-plan= loads =plan.org= from the project root directly — no file picker.
- Both commands fall back to their normal interactive prompts when run outside a project.

The primary way to open your plan is =M-x org-scribe-plan= (or =F8 F8 W p=):

- *Plan already active* → shows the calendar immediately.
- *Plan file exists but not loaded* → loads it silently, then shows the calendar.
- *No plan file found* → offers to create one (project-aware, no prompts).
- *Not in a project, or the gate is =no=* → falls back to =org-scribe-planner-show-current-plan=, or offers to enable the gate first (see Opt-in Gate above).

Plan file discovery still works without a shipped placeholder — the first accepted plan creation writes =plan.org= itself.

*** 5. Plan Creation on Project Creation

After creating a new novel or short story project, you are offered the option to create a matching writing plan immediately. Accepting opens the gate (=# Planner: yes=) and creates the plan; declining closes it (=# Planner: no=) so you are not asked again for that project.

*** 6. Planner Hydra Sub-menu (=W=)

Press =F8 F8 W= to open the planner sub-menu. If the project has declined the planner, this key offers to enable it first instead of opening the submenu.

- =p= - Open project plan (load or create)
- =n= - New plan
- =l= - Load plan
- =u= - Update progress (from word count)
- =d= - Update daily word count
- =r= - Recalculate plan
- =a= - Adjust remaining days
- =m= - Milestones
- =D= - Dashboards menu
- =E= - Enable planner for this project
- =X= - Disable planner for this project
- =q= - Back to main menu

*** 7. Mode-Line Status

When a plan is active and the project's gate is =yes=, the mode line shows today's progress: =[W:actual/target]=.

*** 8. Project Health Integration

=M-x org-scribe-project-health= includes a =* Writing Plan= section when the planner is loaded and the gate is not =no=, showing title, target, current word count and percentage, daily target, end date, days remaining, and whether you are on track or behind. When no plan is active a hint to run =M-x org-scribe-plan= is shown instead. The section is omitted entirely for a project that has declined the planner.

** Opting Out of Individual Features

Set these variables before the planner first loads (e.g., in =early-init.el=):

#+begin_src emacs-lisp
(setq org-scribe-planner-auto-load-plan nil)      ; no auto-load on project open
(setq org-scribe-planner-auto-push-wordcount nil) ; no push after word count
(setq org-scribe-planner-offer-plan-on-create nil); no prompt on new project
(setq org-scribe-planner-show-mode-line nil)      ; no [W:n/n] in mode line
(setq org-scribe-auto-wordcount nil)              ; no full update on every save
#+end_src
