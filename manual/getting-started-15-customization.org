** Understanding Emacs Configuration

All customizations go in your Emacs configuration file:

*Common locations*:
- ~~/.emacs.d/init.el~ (most common)
- ~~/.emacs~
- ~~/.config/emacs/init.el~

*To find yours*:
1. In Emacs: ~C-h v user-init-file RET~
2. The value shown is your config file
3. Open it: ~C-x C-f~ then paste that path

** Two Ways to Customize

*Method 1: Customize Interface* (Beginner-friendly)
- Press ~M-x customize-group RET org-scribe RET~
- Click options, change values
- Click "Apply and Save"
- No Emacs Lisp knowledge needed

*Method 2: Direct Configuration* (More powerful)
- Edit your init file directly
- Add Emacs Lisp code
- More control and documentation
- Can be version-controlled

*This lesson teaches both methods!*

** Emacs Lisp Basics (Quick Primer)

You'll see code like this:

#+BEGIN_SRC emacs-lisp
(setq org-scribe-env-work-theme 'modus-vivendi)
#+END_SRC

*Reading this*:
- ~setq~ = "set variable"
- ~org-scribe-env-work-theme~ = variable name
- ~'modus-vivendi~ = value (the ~'~ means "symbol")

*Types of values*:
- Symbol: ~'poet~, ~'leuven~ (theme/preset names)
- Number: ~80~, ~0.25~ (widths, percentages)
- String: ~"hello"~ (text in quotes)
- Boolean: ~t~ (true) or ~nil~ (false)

Don't worry if this is confusing - just copy the examples!

* Customizing Writing Modes

The writing modes (distraction-free, focus, project, editing) are highly customizable.

** Themes for Writing Modes

Each mode can use a different theme to signal mode changes visually.

*** Current Defaults

#+BEGIN_SRC emacs-lisp
;; Default themes
(setq org-scribe-env-normal-theme nil)   ; nil = leave your theme alone
(setq org-scribe-env-work-theme nil)     ; nil = leave your theme alone
(setq org-scribe-editing-theme 'leuven)  ; Editing mode (leuven ships with Emacs)
#+END_SRC

The writing-mode themes default to ~nil~: out of the box, entering and
leaving a writing mode does *not* change your colours. Set them to a theme
you have installed to get theme switching. If a theme you name is not
installed, org-scribe says so in the echo area and keeps your current theme
rather than signalling an error.

*** Changing Themes

*Popular writing themes*:

For distraction-free mode:
- ~'poet~ - Minimalist, high contrast
- ~'writeroom~ - Very clean
- ~'nord~ - Cool, calming colors
- ~'zenburn~ - Low contrast, easy on eyes
- ~'solarized-light~ - Classic, warm light theme
- ~'modus-operandi~ - Accessible light theme

For editing mode:
- ~'leuven~ - Clean, organized (default)
- ~'modus-operandi~ - Accessible, professional
- ~'ef-light~ - Modern light theme
- ~'spacemacs-light~ - Clean and colorful

*How to change*:

Add to your init file:

#+BEGIN_SRC emacs-lisp
;; Customize writing mode themes
(setq org-scribe-env-work-theme 'modus-vivendi)    ; Dark writing theme
(setq org-scribe-env-normal-theme 'modus-operandi) ; Light normal theme
(setq org-scribe-editing-theme 'ef-light)              ; Light editing theme
#+END_SRC

*Testing themes*:

Before committing, test a theme:
1. ~M-x load-theme RET modus-vivendi RET~
2. See how it looks
3. If you like it, add to config
4. If not, try another: ~M-x load-theme RET zenburn RET~

*** Using Different Themes for Day/Night

Some writers prefer light themes during day, dark at night:

#+BEGIN_SRC emacs-lisp
;; Daytime (9 AM - 6 PM): Light themes
(setq org-scribe-env-work-theme 'modus-operandi)

;; Nighttime (6 PM - 9 AM): Dark themes
;; (You'd need to switch manually or use circadian-mode package)
#+END_SRC

Or install the ~circadian~ package for automatic switching:

#+BEGIN_SRC emacs-lisp
(use-package circadian
  :ensure t
  :config
  (setq circadian-themes '(("9:00" . modus-operandi)
                           ("18:00" . modus-vivendi)))
  (circadian-setup))
#+END_SRC

** Fonts for Writing Modes

Typography matters! Different fonts for different tasks.

*** Font Presets with Fontaine

~org-scribe~ uses the ~fontaine~ package for font management.

*Actual defcustom defaults* (none of these fontaine presets ship with org-scribe — you must define them yourself with =fontaine-set-presets= before the mode that uses them will find anything):

#+BEGIN_SRC emacs-lisp
(setq org-scribe-env-normal-font 'regular)      ; Normal editing
(setq org-scribe-env-work-font 'org-scribe-big) ; Distraction-free mode
(setq org-scribe-editing-fontaine-preset 'editing)  ; Editing mode
#+END_SRC

*** Creating Custom Font Presets

Define your own presets in your init file:

#+BEGIN_SRC emacs-lisp
(setq fontaine-presets
  '((regular
     :default-height 140)           ; Normal size

    (writing-big
     :default-family "iA Writer Mono"
     :default-height 180             ; Larger for writing
     :line-spacing 4)                ; More space between lines

    (editing
     :default-family "Fira Code"
     :default-height 160
     :variable-pitch-family "Libre Baskerville"
     :variable-pitch-height 160)

    (presentation
     :default-height 220)))          ; Very large
#+END_SRC

*Popular writing fonts*:
- **Monospace**: iA Writer Mono, Fira Code, JetBrains Mono, Source Code Pro
- **Variable-pitch**: Libre Baskerville, Crimson Text, ET Book, Merriweather

*Finding font names*:

Run: ~M-x menu-set-font~ to see available fonts, or:

#+BEGIN_SRC emacs-lisp
;; List all available fonts
M-x describe-font RET TAB
#+END_SRC

*** Adjusting Font Size Only

If you just want bigger/smaller text without changing fonts:

#+BEGIN_SRC emacs-lisp
;; Make writing mode font bigger
(setq fontaine-presets
  '((regular
     :default-height 140)    ; Default
    (writing-big
     :default-height 200)))  ; 200 = larger (try 160, 180, 200, 220)
#+END_SRC

*Height scale*:
- 120 = Small
- 140 = Normal
- 160 = Medium large
- 180 = Large
- 200 = Very large
- 220+ = Presentation mode

** Text Width (Column Width)

Control how wide your text appears - crucial for comfortable reading.

*** Writing Mode Width

#+BEGIN_SRC emacs-lisp
;; Default widths
(setq org-scribe-env-work-width 80)     ; Distraction-free: 80 columns
(setq org-scribe-env-normal-width 90)   ; Normal: 90 columns
#+END_SRC

*Adjusting*:

#+BEGIN_SRC emacs-lisp
;; Narrower for focused writing
(setq org-scribe-env-work-width 70)

;; Wider if you have large monitor
(setq org-scribe-env-work-width 100)
#+END_SRC

*Guidelines*:
- 60-70: Very focused, narrow column
- 70-80: Standard comfortable reading (recommended)
- 80-90: Slightly wider
- 90-100: Wide (good for large monitors)
- 100+: Very wide (loses focus)

*Rule of thumb*: 60-90 characters per line is optimal for reading.

*** Editing Mode Width

Editing mode has a fill-column setting:

#+BEGIN_SRC emacs-lisp
;; Default
(setq org-scribe-editing-fill-column-width 90)

;; Adjust to your preference
(setq org-scribe-editing-fill-column-width 100)  ; Wider for more context
#+END_SRC

** Window Panel Sizes (Editing Mode)

Editing mode splits screen into three panels. Adjust their proportions:

#+BEGIN_SRC emacs-lisp
;; Defaults: 25% / 50% / 25%
(setq org-scribe-editing-left-width-percent 0.25)   ; Outline panel (left)
(setq org-scribe-editing-right-width-percent 0.25)  ; Notes panel (right)
;; Center is automatic: 1.0 - left - right = 0.50 (50%)
#+END_SRC

*Alternative layouts*:

Narrower outline, wider manuscript:
#+BEGIN_SRC emacs-lisp
(setq org-scribe-editing-left-width-percent 0.20)   ; 20%
(setq org-scribe-editing-right-width-percent 0.25)  ; 25%
;; Center: 55%
#+END_SRC

Narrower notes, more focus on manuscript:
#+BEGIN_SRC emacs-lisp
(setq org-scribe-editing-left-width-percent 0.25)   ; 25%
(setq org-scribe-editing-right-width-percent 0.20)  ; 20%
;; Center: 55%
#+END_SRC

Balanced three-column:
#+BEGIN_SRC emacs-lisp
(setq org-scribe-editing-left-width-percent 0.33)   ; 33%
(setq org-scribe-editing-right-width-percent 0.33)  ; 33%
;; Center: 34%
#+END_SRC

*Must sum to less than 1.0!*

** Outline Panel Depth (Scenes vs. Chapters)

The outline panel used by Editing mode and Navigate mode is built from Org's
*imenu index*, and that index stops at ~org-imenu-depth~ headings deep. The
Org default is ~2~:

#+BEGIN_SRC emacs-lisp
;; Show scenes (level 3) in the outline panel, not just acts and chapters
(setq org-imenu-depth 3)
#+END_SRC

org-scribe's novel templates put acts at level 1, chapters at level 2 and
*scenes at level 3* — so with the default the panel lists chapters and stops,
one level short of the headings you actually navigate by. Set ~4~ if you also
write beats below scenes; each extra level makes the index slower to build and
the panel longer.

The index is cached per buffer, so after changing this either restart Emacs,
revert the manuscript buffer, or click ~*Rescan*~ at the top of the panel.

Note this is a plain Org variable, not an org-scribe one — raising it also
improves ~M-x imenu~, ~consult-imenu~ and anything else that reads the index.

** Complete Writing Modes Configuration Example

Put this in your init file:

#+BEGIN_SRC emacs-lisp
;;; Writing Modes Customization

;; === THEMES ===
(setq org-scribe-env-normal-theme 'modus-operandi)  ; Light theme normally
(setq org-scribe-env-work-theme 'poet)              ; Clean theme for writing
(setq org-scribe-editing-theme 'leuven)                 ; Organized for editing

;; === FONTS ===
(setq org-scribe-env-normal-font 'regular)
(setq org-scribe-env-work-font 'writing-big)
(setq org-scribe-editing-fontaine-preset 'editing)

;; === TEXT WIDTHS ===
(setq org-scribe-env-work-width 75)                  ; Comfortable reading width
(setq org-scribe-env-normal-width 90)                ; Normal editing width
(setq org-scribe-editing-fill-column-width 90)          ; Editing mode width

;; === EDITING MODE PANELS ===
(setq org-scribe-editing-left-width-percent 0.25)       ; Outline: 25%
(setq org-scribe-editing-right-width-percent 0.25)      ; Notes: 25%
                                                      ; Manuscript: 50% (automatic)
(setq org-scribe-editing-right-panel 'notes)            ; What the right pane shows

;; === OUTLINE PANEL DEPTH ===
(setq org-imenu-depth 3)                                ; List scenes, not just chapters
#+END_SRC

** What the Right Panel Shows

By default Editing mode's right pane shows your project notes file. ~org-scribe-editing-right-panel~ changes that:

| Value             | Right panel shows                                        |
|-------------------+----------------------------------------------------------|
| ~notes~ (default) | The project notes file, the same one captures write to   |
| ~edits~           | A live index of your inline edit markers, rebuilt on save |
| ~revision~        | The project's ~revision.org~                             |
| a string          | A project-relative path, e.g. ~"notes/research.org"~     |
| a function        | Called with the manuscript file name; returns a file     |

#+BEGIN_SRC emacs-lisp
;; During a revision pass, keep the outstanding edits beside the text
(setq org-scribe-editing-right-panel 'edits)
#+END_SRC

If the requested file can't be found, the pane falls back to the notes file rather than opening nothing.

* Customizing Edit Markers

The inline ~*EDIT*~ / ~*NOTE*~ markers you leave in the manuscript (lesson 14) have two settings.

** Marker Categories

An ~*EDIT*~ carries a category before a ~" - "~ separator, and the edit index groups by it:

#+BEGIN_SRC emacs-lisp
;; Default
(setq org-scribe-edit-categories '("plot" "scene" "character" "prose"))

;; Add your own
(setq org-scribe-edit-categories '("plot" "scene" "character" "prose" "pacing" "research"))
#+END_SRC

This one variable drives both ends: the index groups by it, and the bundled Tempel ~edit~ snippet prompts from it, so they cannot disagree. A marker whose category is missing, empty or unrecognized lands under ~other~ - never dropped.

** Empty Categories in the Index

#+BEGIN_SRC emacs-lisp
;; Default: show every category, even empty ones (index doubles as a checklist)
(setq org-scribe-edits-index-show-empty-categories t)

;; Compact: only categories that actually have markers
(setq org-scribe-edits-index-show-empty-categories nil)
#+END_SRC

** The Plain-Text Fallback

~org-scribe-edit-string~ is the regexp used by ~org-scribe-search-edits-rgrep~ (the ~C-u~ variant of ~F8 F8 6~), not by the structured index. Customize it if you use marker styles of your own:

#+BEGIN_SRC emacs-lisp
(setq org-scribe-edit-string "\\*EDIT\\*\\|\\*NOTE\\*\\|TODO-REVISE")
#+END_SRC

* Customizing Language Tools

Configure the dictionary and synonym tools.

** Synonym Window Width

The synonym window opens on the right. Adjust its width:

#+BEGIN_SRC emacs-lisp
;; Default
(setq org-scribe-sinonimo-window-width 80)

;; Narrower (good for small screens)
(setq org-scribe-sinonimo-window-width 60)

;; Wider (more content visible)
(setq org-scribe-sinonimo-window-width 100)
#+END_SRC

This applies to both offline and online results.

** Definition Source

Definitions can come from a local Wikcionario served by kiwix-serve instead
of the online RAE. Lesson 12 covers the setup (a 566 MB download and a
background service).

#+BEGIN_SRC emacs-lisp
;; 'auto (default)  — the local server when it answers, the online RAE otherwise
;; 'wikcionario     — local only; never queries the network
;; 'rae-api         — always the online RAE
(setq org-scribe-dictionary-backend 'auto)

;; Where the local server is listening
(setq org-scribe-wikcionario-url "http://localhost:8080")

;; Which ZIM to query; nil asks the server what it is serving
(setq org-scribe-wikcionario-book nil)

;; How long to wait for the local server before giving up.  Only paid on the
;; first lookup of a session.
(setq org-scribe-wikcionario-timeout 3)
#+END_SRC

org-scribe never starts or supervises kiwix-serve — it probes and reports.
Availability is cached per session, so if you start the server after Emacs,
press ~C-u~ before the lookup (~C-u F8 F8 d~) or run
~M-x org-scribe-wikcionario-clear-cache~.

** Thesaurus Source

Synonym lookup can read a thesaurus on your own disk instead of loading a
web page. Install the data with your system package manager — ~sudo apt
install mythes-es~ on Debian/Ubuntu — and it is used automatically. Lesson
12 covers the install and what changes.

#+BEGIN_SRC emacs-lisp
;; 'auto (default)  — offline when the data is installed, online otherwise,
;;                    and online for a word with no local entry
;; 'mythes          — offline only; a miss is reported, never goes online
;; 'wordreference   — always the WordReference page
(setq org-scribe-thesaurus-backend 'auto)
#+END_SRC

~'mythes~ is worth setting on a metered connection, or when you want to know
exactly what your local data covers rather than having gaps papered over.

** Thesaurus Location and Language

Only needed if the data is somewhere unusual, or you want a language other
than the default:

#+BEGIN_SRC emacs-lisp
;; Where the th_*_v2.dat / th_*_v2.idx pairs live
(setq org-scribe-mythes-directory "/usr/share/mythes/")

;; Which one to read
(setq org-scribe-mythes-language "es_ES")   ; es_MX, en_US, ...
#+END_SRC

If no thesaurus matches exactly, another variant of the same base language
is used — so ~es_MX~ still works when only ~es_ES~ is installed.

Check what org-scribe found with ~(org-scribe-mythes-files)~; ~nil~ means it
found nothing.

** Lemmatization Dictionary

Lemmatization is what lets a lookup for ~corriendo~ find the thesaurus entry
for ~correr~. It uses hunspell, which you very likely already have installed
for spell checking, and follows the thesaurus language by default.

#+BEGIN_SRC emacs-lisp
;; nil (default) — follow `org-scribe-mythes-language'
;; Or name a hunspell dictionary explicitly:
(setq org-scribe-lemma-dictionary "es_ES")
#+END_SRC

Check it with ~(org-scribe-lemma "corriendo")~, which should return
~"correr"~. If you install a dictionary while Emacs is running, run
~M-x org-scribe-lemma-clear-cache~ so it is picked up.

Without hunspell nothing breaks — only the exact word you typed is looked
up.

** Example Configuration

#+BEGIN_SRC emacs-lisp
;;; Language Tools Customization

;; Side window width (definitions and synonyms both use it)
(setq org-scribe-sinonimo-window-width 70)

;; Prefer local sources, fall back to the web
(setq org-scribe-dictionary-backend 'auto)
(setq org-scribe-thesaurus-backend 'auto)

;; Mexican Spanish for both thesaurus and morphology
(setq org-scribe-mythes-language "es_MX")

* Customizing Export Settings

Control how your manuscript exports to different formats.

** Scene Break Formatting

The scene break macro (~{{{scene-break}}}~) outputs differently per format:

#+BEGIN_SRC emacs-lisp
;; Defaults
(setq org-scribe-scene-break-replacements
  '((ascii . "\n***\n\n")
    (md . "\n***\n\n")
    (html . "<br><br><br>\n")
    (latex . "\\vspace{\\baselineskip}\\vspace{\\baselineskip}\\vspace{\\baselineskip}\n")
    (t . "\n\n\n")))  ; Default for other backends
#+END_SRC

*** Customizing Scene Breaks

*Want centered asterisks in LaTeX?*

#+BEGIN_SRC emacs-lisp
(setq org-scribe-scene-break-replacements
  '((latex . "\\begin{center}***\\end{center}\n")
    (html . "<p style='text-align:center;'>***</p>\n")
    (t . "\n***\n\n")))
#+END_SRC

*Want ornamental break*:

#+BEGIN_SRC emacs-lisp
(setq org-scribe-scene-break-replacements
  '((latex . "\\begin{center}\\text{\\Large ❦}\\end{center}\n")
    (html . "<p style='text-align:center; font-size: 1.5em;'>❦</p>\n")
    (t . "\n❦\n\n")))
#+END_SRC

*Want simple blank space*:

#+BEGIN_SRC emacs-lisp
(setq org-scribe-scene-break-replacements
  '((latex . "\\vspace{2\\baselineskip}\n")
    (html . "<br><br>\n")
    (t . "\n\n")))
#+END_SRC

* Language Settings (English/Spanish)

~org-scribe~ supports both English and Spanish workflows.

** Setting Template Language

Controls which templates are used when creating projects:

#+BEGIN_SRC emacs-lisp
;; Default: English
(setq org-scribe-template-language 'en)

;; For Spanish
(setq org-scribe-template-language 'es)
#+END_SRC

*What this affects*:
- Template directory selection (~novel-en~ vs ~novel-es~)
- File names (~novel.org~ vs ~novela.org~, ~notes~ vs ~notas~)
- Template content language
- Default scene/chapter templates

** Spelling Dictionary Per Project

A project is written in one language, so the spelling dictionary belongs to the
project rather than to each file. When org-scribe creates a project it writes a
~.dir-locals.el~ at the project root pinning ~ispell-local-dictionary~, and
every file in the project — manuscript, notes, planning files, and anything you
add later — picks it up automatically, with no prompt.

Which dictionary name gets written comes from this alist:

#+BEGIN_SRC emacs-lisp
;; Default
(setq org-scribe-ispell-dictionaries '((en . "en_US")
                                       (es . "es_ES")))

;; Regional variants
(setq org-scribe-ispell-dictionaries '((en . "en_GB")
                                       (es . "es_MX")))
#+END_SRC

The key is the *project* language (from ~.org-scribe-project~), not your global
~org-scribe-template-language~ default — so a Spanish project keeps its Spanish
dictionary even when your default is English. A language with no entry, or an
entry of ~nil~, means "write no dictionary" rather than guessing one.

To apply a change to projects that already exist, or to give an older project
its first ~.dir-locals.el~, run ~M-x org-scribe-update-dir-locals~ (~F8 F8 L D~)
inside the project. It reads the language from the marker file and asks before
replacing an existing file. The project health report flags a missing or
mismatched dictionary in its Overview.

If you manage directory-local variables yourself, turn the whole thing off:

#+BEGIN_SRC emacs-lisp
(setq org-scribe-write-dir-locals nil)
#+END_SRC

Nothing else in org-scribe reads the generated file — it exists purely for
Emacs's own spell checking. A per-file ~# Local Variables:~ block still
overrides it, and ~guess-language~, if you use it, overrides both.

** Bilingual Setup

If you write in both languages, you can:

*Option 1: Switch as needed*

#+BEGIN_SRC emacs-lisp
;; In init file, set default
(setq org-scribe-template-language 'en)

;; When starting Spanish project, temporarily change:
;; M-x set-variable RET org-scribe-template-language RET 'es RET
;; Then create project
#+END_SRC

*Option 2: Use both template sets*

#+BEGIN_SRC emacs-lisp
;; Define functions for each language
(defun my-new-english-novel ()
  "Create English novel project."
  (interactive)
  (let ((org-scribe-template-language 'en))
    (call-interactively 'org-scribe-create-novel-project)))

(defun my-new-spanish-novel ()
  "Create Spanish novel project."
  (interactive)
  (let ((org-scribe-template-language 'es))
    (call-interactively 'org-scribe-create-novel-project)))
#+END_SRC

Now you have dedicated commands for each language!

* Modifying Project Templates

Customize the templates to match your specific needs.

** Accessing Templates

*Method 1: Via Command*

#+BEGIN_EXAMPLE
M-x org-scribe-edit-templates
#+END_EXAMPLE

Opens the template directory in Dired.

*Method 2: Direct Path*

Templates are in the package directory:
#+BEGIN_EXAMPLE

** Common Template Modifications

*** Adding Your Writing Goals

Edit ~novel.org.template~ or ~story.org.template~:

#+BEGIN_EXAMPLE

*** Adding Custom Planning Files

For novels, add a new planning file:

1. Create ~motivations.org.template~ in template directory:

#+BEGIN_EXAMPLE
#+TITLE: Character Motivations - ${TITLE}
#+AUTHOR: ${AUTHOR}
#+DATE: ${DATE}

,* Protagonist Motivations

,** External Goals
What they want in the world

,** Internal Needs
What they need to grow

,* Antagonist Motivations
...
#+END_EXAMPLE

2. It will be included in new novel projects automatically!

** Short Story vs Novel Templates

Remember the differences:

*Novel templates* (~org-scribe-templates/novel-en/~):
- 12-13 files
- Separate objects/ directory
- Complex structure

*Short story templates* (~org-scribe-templates/short-story-en/~):
- 3 files
- Simplified structure
- Combined notes file

Modify the appropriate set for your needs!

** Default Project Location

#+BEGIN_SRC emacs-lisp

(defun my-writing-create-novel ()
  "Create novel in my default directory."

** File and Directory Name Preferences

Project file and directory names are not configurable. org-scribe
resolves them from the fixed bilingual pairs its templates ship —
~novel.org~ / ~novela.org~ for the manuscript, ~notes/~ / ~notas/~ for
the notes directory, and so on — and the manuscript pair also drives
project type detection, so renaming it would leave the project
unrecognized. Keep the names the template gave you.

* Troubleshooting Customization

** "My changes aren't working!"

*Check*:
1. Did you save the init file? (~C-x C-s~)
2. Did you reload? (~M-x load-file~)
3. Typos in variable names?
4. Syntax errors? (missing quotes, parentheses)

*Finding syntax errors*:

Look in ~*Messages*~ buffer:
- ~C-h e~ (view-echo-area-messages)
- Look for error messages in red

** "Theme/font not found"

*Error*: "Cannot find theme 'my-theme'"

*Solution*:
1. Check theme is installed: ~M-x package-list-packages~
2. Install if missing: ~M-x package-install RET theme-name RET~
3. Or remove from config if you don't want it

*Error*: "Font not available"

*Solution*:
1. Check font installed on system
2. Use ~M-x menu-set-font~ to see available fonts
3. Update config with available font name

** "Configuration makes Emacs slow"

*Possible causes*:
- Too many packages loading at startup
- Theme changes triggering expensive operations

*Solutions*:
1. Use ~use-package~ with ~:defer t~ for lazy loading
2. Profile startup: ~M-x emacs-init-time~
3. Simplify: disable customizations one by one

** "I broke everything!"

*Emergency recovery*:

1. Start Emacs with: ~emacs -Q~ (ignores config)
2. Open init file normally
3. Find and fix/comment out problematic section
4. Save
5. Restart Emacs normally

*Or*: Move init file temporarily:
#+BEGIN_SRC bash
mv ~/.emacs.d/init.el ~/.emacs.d/init.el.backup
#+END_SRC

Start Emacs, fix backup file, move back.
