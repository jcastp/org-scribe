* Introduction

This document provides a comprehensive index of all features in the ~org-scribe~ package. Each feature is briefly described in a paragraph. Detailed documentation for each feature will be available in separate files linked from this index.

*Version*: 0.7.0 (includes merged emacs-org-scribe-template functionality)

*Package Overview*: ~org-scribe~ is a comprehensive toolkit for creative writers working in Org-mode, providing everything from project templates to export filters for novelists and short story writers.

* Feature Categories

This package organizes features into the following categories:

1. [[#project-management][Project Management]] - Creating and organizing writing projects
2. [[#writing-modes][Writing Modes]] - Distraction-free and specialized writing environments
3. [[#word-counting-tracking][Word Counting & Tracking]] - Counting words and tracking progress
4. [[#capture-system][Capture System]] - Quick capture of characters, locations, and notes
5. [[#linking-system][Linking System]] - ID-based linking for characters, locations, and plot threads; entity tooltips
6. [[#search-tools][Search Tools]] - Find scenes by character, plot, location, or PoV
7. [[#templates][Templates]] - Scene and chapter insertion templates; scene word-count update
8. [[#dictionary-language][Dictionary & Language Tools]] - offline/online definitions and synonyms, lemmatization, translations
9. [[#export-tools][Export Tools]] - Scene break filters and export presets
10. [[#column-view][Column View Enhancements]] - Clean display of ID links in column view
11. [[#analysis-tools][Analysis Tools]] - Project health report and aggregated statistics
12. [[#ui-navigation][UI & Navigation]] - Hydra menu and keybindings
13. [[#configuration][Configuration]] - Customization options
14. [[#integrations][Writing Planner]] - Bundled goal-oriented writing plan module

* Project Management
:PROPERTIES:
:CUSTOM_ID: project-management
:END:

** Novel Project Creation (~org-scribe-create-novel-project~)

Creates a complete novel project structure from customizable templates. This function sets up a comprehensive 12-13 file project including the main manuscript (novel.org), statistics tracking, revision notes, and separate planning files for characters, locations, plot, timeline, and objects. The project is automatically initialized as a git repository with an initial commit, and all templates support variable substitution for title, author, and date. The structure supports both English and Spanish workflows.

*Status*: Fully implemented | *Hydra*: Not in menu (interactive only) | *Module*: ~templates/org-scribe-project.el~

** Short Story Project Creation (~org-scribe-create-short-story-project~)

Creates a minimal short story project structure optimized for shorter works (1,000-20,000 words). Unlike novel projects, short story projects use only 3 files: README.org, story.org (or cuento.org for Spanish), and a consolidated notes.org file that combines character sketches, plot outline, and research. Word counting is integrated directly into the story file rather than maintained separately. This streamlined structure reduces overhead for quick projects while maintaining essential planning features.

*Status*: Fully implemented | *Hydra*: Not in menu (interactive only) | *Module*: ~templates/org-scribe-project.el~

** Project Type Detection (~org-scribe-project-type~)

Automatically detects whether a project is a novel, short story, or unknown type by examining the directory structure and marker files. Detection checks for the .org-scribe-project marker file first, then looks for characteristic indicators: the presence of a objects/ directory suggests a novel, while story.org/cuento.org indicates a short story. This detection is cached per project root for performance and enables other features (like capture functions) to adapt their behavior based on project type.

*Status*: Fully implemented | *Hydra*: N/A (internal function) | *Module*: ~core/org-scribe-core.el~

** Project File Navigation (~org-scribe-open-project-file~)

Provides quick navigation to any file in the current writing project using completion. Detects the project root, scans for all org files in the project structure, and presents them in a searchable list. This works with both novel projects (with many specialized files) and short story projects (with fewer files). The function intelligently handles bilingual projects, showing both English and Spanish file names when present.

*Status*: Fully implemented | *Hydra*: ~o~ (Insert section) | *Module*: ~templates/org-scribe-project.el~

** Template Language Selection (~org-scribe-template-language~)

Controls which language templates are used when creating new projects. Set to ~'en~ for English templates (novel.org, notes/, characters.org) or ~'es~ for Spanish templates (novela.org, notas/, personajes.org). This affects both novel and short story project creation. Template directories are structured as org-scribe-templates/novel-en/, novel-es/, short-story-en/, and short-story-es/, allowing complete bilingual support throughout the package.

*Status*: Fully implemented | *Hydra*: N/A (configuration) | *Module*: ~templates/org-scribe-project.el~

** Project Spelling Dictionary (~org-scribe-update-dir-locals~)

Writes a ~.dir-locals.el~ at the project root pinning ~ispell-local-dictionary~ to the project's language, so every file in the project — manuscript, planning files, notes, journal, and anything created later by capture or the planner — spell checks against the right dictionary with no per-file setup. Created automatically alongside the ~.org-scribe-project~ marker file, before the initial git commit; the marker file remains the single source of truth for the language and the dictionary is derived from it. The variable written carries a ~safe-local-variable~ property, so Emacs applies it silently rather than asking the writer to approve a local variables list on every open. The interactive command creates or refreshes the file for an existing project (asking before replacing one), which is how projects created before this feature — or projects whose configured dictionary changed — catch up; the project health report flags a missing or mismatched file. A per-file ~Local Variables~ block still overrides the project-wide setting, and ~guess-language~ overrides both.

*Status*: Fully implemented | *Hydra*: ~D~ (Links & Upkeep submenu) | *Module*: ~templates/org-scribe-project.el~

** Git Integration

Automatically initializes a git repository for new projects and creates an initial commit after template processing. This provides version control from the start of a project, enabling writers to track changes to their manuscript and planning documents. The .org-scribe-project marker file is included in the initial commit. Projects can be easily pushed to remote repositories for backup and collaboration.

*Status*: Fully implemented | *Hydra*: N/A (automatic) | *Module*: ~templates/org-scribe-project.el~

* Writing Modes
:PROPERTIES:
:CUSTOM_ID: org-scribe-modes
:END:

** Distraction-Free Writing Mode (~org-scribe-writing-env-mode~)

Activates a distraction-free writing environment optimized for focused writing sessions. This mode switches to a specialized writing theme (customizable via ~org-scribe-env-work-theme~), applies a larger org-scribe-optimized font preset, and enables writeroom-mode with centered text at a comfortable width (default 80 columns). The mode changes visual presentation without affecting file content, and all settings restore automatically when the mode is disabled. Only one writing mode can be active at a time for clean state management.

*Status*: Fully implemented | *Hydra*: ~m~ (Workspace section) | *Module*: ~modes/org-scribe-modes.el~

** Focus Writing Mode (~org-scribe-writing-env-mode-focus~)

Extends the distraction-free writing mode by adding automatic narrowing to the current org section. This creates an ultra-focused environment where only the current scene or chapter is visible, eliminating distractions from other parts of the manuscript. The mode activates the full distraction-free environment (theme, font, writeroom) and then narrows the buffer to the org subtree at point. When disabled, it widens the buffer back to full view and restores the normal environment.

*Status*: Fully implemented | *Hydra*: ~f~ (Workspace section) | *Module*: ~modes/org-scribe-modes.el~

** Project Writing Mode (~org-scribe-project-mode~)

Opens a project navigation environment by displaying both treemacs (showing the project file tree) and imenu-list (showing the current file's outline) in side windows. This creates a three-panel layout: file tree on the left, main document in the center, and document outline on the right. Ideal for navigating large projects with many files and long documents. The mode gracefully handles missing dependencies (treemacs, imenu-list) with warnings if they're not available. Focus automatically returns to the original buffer after opening the side panels.

*Status*: Fully implemented | *Hydra*: ~v~ (Workspace section, "navigate") | *Module*: ~modes/org-scribe-modes.el~

** Editing Mode (~org-scribe-editing-mode~)

Creates a specialized three-panel layout optimized for editing and revision work. The main document appears in the center with comfortable visual-fill-column formatting, while side panels on the left and right can display reference files (notes, character profiles, timeline, etc.). This mode uses a bright editing theme (default: leuven) for clear visibility of markup and structure. Panel widths are customizable via ~org-scribe-editing-left-width-percent~ and ~org-scribe-editing-right-width-percent~. The mode includes font preset support via fontaine for optimal editing clarity.

*Status*: Fully implemented | *Hydra*: ~e~ (Workspace section) | *Module*: ~modes/org-scribe-modes.el~

** Mode Mutual Exclusivity

All four writing modes are mutually exclusive - activating one automatically deactivates any currently active mode. This prevents conflicting visual settings and state management issues. Each mode tracks its own state in buffer-local variables and provides clean activation/deactivation functions. When switching modes, the previous mode fully restores settings (theme, font, window configuration) before the new mode applies its configuration, ensuring smooth transitions without visual artifacts.

*Status*: Fully implemented | *Hydra*: N/A (automatic behavior) | *Module*: ~modes/org-scribe-modes.el~

* Word Counting & Tracking
:PROPERTIES:
:CUSTOM_ID: word-counting-tracking
:END:

** Accurate Word Counting (~org-scribe-ews-org-count-words~)

Provides accurate word counting that excludes Org-mode metadata (properties, drawers, comments, keywords, tags) to count only actual narrative content. Delegates to ~org-context-extended~ for precise context-aware counting. Can count the current heading and add the word count as a ~:WORDCOUNT:~ property, count the entire buffer, or count from the current heading down through all subheadings. This feature populates properties that feed into progress tracking tables and ensures word count accuracy for writers who use extensive org metadata.

*Status*: Fully implemented | *Hydra*: ~a~ (Tools section) | *Module*: ~counting/org-scribe-wordcount.el~

** Interactive Word Count Display (~org-scribe-wordcount~)

Displays an interactive word count for the current region or buffer, delegating to ~org-context-extended~ when available for accurate counts that exclude Org metadata (falling back to a plain count, with a warning, when that package is absent). This is org-scribe's own unified word-count dispatcher, not a raw call into the external package: with no prefix argument it just reports a count; with ~C-u~ it refreshes ~:WORDCOUNT:~ on every heading in the buffer (~org-scribe-ews-org-count-words~); with ~C-u C-u~ it refreshes ~:WORDCOUNT:~ only on scene-level headings in the current subtree (~org-scribe-update-scene-wordcounts~).

*Status*: Fully implemented | *Hydra*: ~w~ (Tools section) | *Module*: ~counting/org-scribe-wordcount.el~

** Progress Tracking Tables (~org-generate-wordcount-table~)

Generates dynamic progress tracking tables that combine word counts from ~:WORDCOUNT:~ properties with target goals from ~:WORD-OBJECTIVE:~ properties to calculate completion percentages automatically. The tables show hierarchical structure (Acts → Chapters → Scenes) with columns for current wordcount, objective, and auto-calculated progress. Tables are created with ~#+BEGIN: org-generate-wordcount-table~ and updated by pressing ~C-c C-c~ — this dynamic block is implemented directly in org-scribe, not by any external package.

*Status*: Fully implemented | *Hydra*: Not in menu (dynamic block, updated via ~C-c C-c~) | *Module*: ~counting/org-scribe-wordcount.el~

** Word Count Properties

The package uses two standard properties for word count management: ~:WORDCOUNT:~ (auto-calculated actual count) and ~:WORD-OBJECTIVE:~ (manually set target). These properties enable org-mode's powerful property-based features including columnview summaries, searches, and dynamic blocks. Properties can be added to any heading level (scene, chapter, act, or entire novel), creating flexible tracking granularity. The properties integrate with the linking system, appearing in search results and column view displays.

*Status*: Fully implemented | *Hydra*: N/A (property standard) | *Module*: Multiple modules

* Capture System
:PROPERTIES:
:CUSTOM_ID: capture-system
:END:

** Project-Aware Note Capture (~org-scribe-capture-to-file~)

Captures quick notes to the appropriate notes file for the current project type. For novel projects, notes go to notes/notes.org under a "Notes" heading. For short story projects, notes go to the consolidated notes.org file under its "Notes" heading. The capture template includes a timestamp and supports initial content from the region. Files are auto-created if missing with proper structure. This provides a quick way to capture ideas without leaving the writing flow.

*Status*: Fully implemented | *Hydra*: ~n~ (Capture section) | *Module*: ~capture/org-scribe-capture.el~

** Character Profile Capture (~org-scribe-capture-character~)

Opens a comprehensive character capture template that prompts for all essential character information: name, role (protagonist/antagonist/supporting/minor), age, gender, occupation, and first appearance chapter. The template includes structured sections for physical description, personality traits, background, goals/motivation/conflict (both internal and external), character arc, and relationships. Characters are automatically assigned unique IDs via ~%(org-id-new)~ for the linking system. Captures go to objects/characters.org (novels) or notes.org under "Characters" (short stories).

*Status*: Fully implemented | *Hydra*: ~F8 F8 k h~ (Manage → Capture entity submenu) | *Module*: ~capture/org-scribe-capture.el~

** Location Profile Capture (~org-scribe-capture-location~)

Captures detailed location profiles with prompts for name, type (city/building/room/natural/region/country), importance (major/supporting/minor), first appearance, climate, and population. The template includes sections for general description, geography, cultural aspects & society, history, notable features, plot importance, specific places, atmosphere & mood, and map references. Locations receive automatic unique IDs for the linking system. Captures go to objects/locations.org (novels) or notes.org under "Setting → Locations" (short stories).

*Status*: Fully implemented | *Hydra*: ~F8 F8 k l~ (Manage → Capture entity submenu) | *Module*: ~capture/org-scribe-capture.el~

** Object Profile Capture (~org-scribe-capture-object~)

Captures important objects with prompts for name, type (magical/artifact/weapon/tool/symbolic/technology), owner, first appearance, and status (active/lost/destroyed/hidden). The template structures sections for physical description, origin, properties, plot importance, object history, symbolism, current location, and rules & limitations. Objects get unique IDs automatically. Particularly useful for tracking magical items, MacGuffins, symbolic objects, or important props. Captures go to objects/objects.org (novels) or notes.org under "Objects" (short stories).

*Status*: Fully implemented | *Hydra*: ~F8 F8 k b~ (Manage → Capture entity submenu, "oBject") | *Module*: ~capture/org-scribe-capture.el~

** Timeline Event Capture (~org-scribe-capture-timeline~)

Captures story timeline events with prompts for event name, type (action/revelation/character/world/backstory), relevance level, date/time in story, duration, characters involved, location, and chapter. The template includes sections for description, consequences, and connections to other events. Events receive automatic unique IDs. This is essential for tracking complex timelines, multiple plot threads, or stories with non-linear narratives. Captures go to objects/timeline.org (novels) or notes.org under "Timeline" (short stories).

*Status*: Fully implemented | *Hydra*: ~F8 F8 k t~ (Manage → Capture entity submenu) | *Module*: ~capture/org-scribe-capture.el~

** Plot Thread Profile Capture (~org-scribe-capture-plot-thread~)

Captures plot thread profiles with prompts for name and type (Main Plot, Subplot, Arc, Theme, or Motif). The template includes sections for description, connection to the main plot, key scenes where the thread appears, and resolution notes. Plot threads receive automatic unique IDs for the linking system. This capture is intentionally minimal - designed to quickly record a new thread when you notice it emerging during writing, with the intention to elaborate during planning sessions. Captures go to objects/plot.org (novels) or notes.org under "Plot Outline" (short stories).

*Status*: Fully implemented | *Hydra*: ~F8 F8 k g~ (Manage → Capture entity submenu) | *Module*: ~capture/org-scribe-capture.el~

** Auto-Creation of Target Files

All capture functions automatically create their target files if they don't exist. For novel projects, separate objects/ files are created with appropriate structure. For short story projects, a comprehensive notes.org file is created with all necessary headings (Characters, Plot Outline, Setting → Locations, Objects, Timeline, Research, Revision Notes, Random Ideas). This ensures capture works even in brand new or minimal projects, reducing friction for writers who prefer to build structure as they write.

*Status*: Fully implemented | *Hydra*: N/A (automatic) | *Module*: ~capture/org-scribe-capture.el~

** Bilingual Capture Support

Capture functions automatically detect and work with both English and Spanish project structures. File names adapt: characters.org/personajes.org, locations.org/localizaciones.org, objects.org/objetos.org, timeline.org/cronologia.org, notes.org/notas.org. The template *content* itself — headlines, ~%^{...}~ prompts, and section headings — is also fully localized: it follows ~org-scribe-project-language~, which reads the project's own ~# Language:~ marker in ~.org-scribe-project~ (falling back to ~org-scribe-template-language~ only when the project predates that marker). This allows Spanish-language writers to work entirely in their native language while using all package features, regardless of the global ~org-scribe-message-language~ UI setting.

*Status*: Fully implemented | *Hydra*: N/A (automatic) | *Module*: ~capture/org-scribe-capture.el~

* Linking System
:PROPERTIES:
:CUSTOM_ID: linking-system
:END:

** Character ID-Based Linking

Provides ID-based links between scene properties and character profiles, allowing click-to-navigate from scene ~:PoV:~ and ~:Characters:~ properties directly to character profile headings. Characters captured via ~org-scribe-capture-character~ automatically get unique IDs via ~%(org-id-new)~ in the template. Menu-based functions (~org-scribe-set-pov-character~, ~org-scribe-set-scene-characters~) allow selecting characters from a searchable list and auto-insert ID links. Links are stable across character name changes and work with org's native link following (~C-c C-o~).

*Status*: Fully implemented | *Hydra*: Tag Scene section (~p~/~h~/~j~) plus ~F8 F8 L c~ for one-time setup | *Module*: ~linking/org-scribe-character-links.el~

** Set PoV Character (~org-scribe-set-pov-character~)

Scans the characters file for all character profiles (identified by ~:Role:~ or ~:TYPE:~ properties and unique IDs), presents them in a completion menu, and inserts the selected character as an ID link in the current scene's ~:PoV:~ property. The link format is ~[[id:unique-id][Character Name]]~, providing both human readability and stable navigation. This function saves time compared to manually typing character names and ensures consistency across the manuscript.

*Status*: Fully implemented | *Hydra*: ~p~ (Tag Scene section, "set PoV") | *Module*: ~linking/org-scribe-character-links.el~

** Set Scene Characters (~org-scribe-set-scene-characters~)

Similar to setting PoV, but allows multi-selection of characters for the ~:Characters:~ property. Characters are presented in a completion menu where you can select multiple names (one at a time, pressing RET between selections, empty input to finish). The function creates comma-separated ID links like ~[[id:id1][Alice]], [[id:id2][Bob]]~ in the Characters property. This tracks which characters appear in each scene, enabling character timeline generation and character-based searches.

The tagging is not additive. When set the scene characters, the list is emptied and recreated from scratch with the characters that were selected in that tagging action.

*Status*: Fully implemented | *Hydra*: ~h~ (Tag Scene section, "set characters") | *Module*: ~linking/org-scribe-character-links.el~

** Jump to PoV Character (~org-scribe-jump-to-pov-character~)

Reads the ~:PoV:~ property of the current scene heading, extracts the ID from the link, and navigates directly to that character's profile using org's ID-based navigation. Works in both the same file and across files. After jumping, you can return to the original location using ~C-c &~ (org-mark-ring-goto). This provides instant access to character details while writing scenes, eliminating manual searching through the characters file.

*Status*: Fully implemented | *Hydra*: ~j~ (Tag Scene section, "jump to PoV") | *Module*: ~linking/org-scribe-character-links.el~

** Location ID-Based Linking

Provides the same ID-based linking infrastructure for locations as exists for characters. Location profiles captured via ~org-scribe-capture-location~ get automatic unique IDs. The ~org-scribe-set-scene-locations~ function presents a multi-select menu of all locations in the project and inserts ID links into the scene's ~:Location:~ property. This enables click-to-navigate to detailed location profiles and supports location-based searches to find all scenes set in a particular place.

*Status*: Fully implemented | *Hydra*: ~l~ (Tag Scene section) plus ~F8 F8 L o~ for one-time setup | *Module*: ~linking/org-scribe-location-links.el~

** Set Scene Locations (~org-scribe-set-scene-locations~)

Scans objects/locations.org (or notes.org for short stories) for all location entries with ~:Type:~ properties and IDs, presents them in a multi-select completion menu, and inserts comma-separated ID links in the ~:Location:~ property. Locations can include cities, buildings, rooms, natural settings, regions, or countries. Multiple locations per scene are supported (useful for travel scenes or scenes that span locations). The menu shows location names extracted from heading text or ~:NAME:~ properties.

*Status*: Fully implemented | *Hydra*: ~l~ (Tag Scene section, "set locations") | *Module*: ~linking/org-scribe-location-links.el~

** Plot Thread ID-Based Linking

Provides ID-based linking for plot threads, enabling tracking of which plot lines appear in which scenes. Plot thread profiles in objects/plot.org receive automatic IDs. The ~org-scribe-set-scene-plot-threads~ function presents a multi-select menu of all plot threads and inserts ID links into the scene's ~:Plot:~ property. This enables generating plot thread timelines (showing which scenes advance which plots), analyzing plot distribution, and identifying gaps in plot coverage.

*Status*: Fully implemented | *Hydra*: ~g~ (Tag Scene section) plus ~F8 F8 L p~ for one-time setup | *Module*: ~linking/org-scribe-plot-links.el~

** Set Scene Plot Threads (~org-scribe-set-scene-plot-threads~)

Scans the plot file for all plot thread entries (headings with ~:Type:~ property set to "Main", "Subplot", "Arc", or similar, plus unique ID), presents them in a multi-select menu, and inserts ID links in the ~:Plot:~ property as ~[[id:id1][Main Plot]], [[id:id2][Romance Subplot]]~. Multiple plot threads per scene are common in complex narratives. This function helps writers ensure plot threads are advanced regularly and no plots are abandoned or forgotten.

*Status*: Fully implemented | *Hydra*: ~g~ (Tag Scene section, "set plot threads") | *Module*: ~linking/org-scribe-plot-links.el~

** Jump to Plot Thread (~org-scribe-jump-to-plot-thread~)

Reads the ~:Plot:~ property of the current scene, presents a menu if multiple plot threads are linked, and navigates to the selected plot thread's profile using ID-based navigation. This provides quick access to plot thread details, story beats, and planning notes while writing scenes that advance that plot. The jump works across files and supports returning via org-mark-ring (~C-c &~).

*Status*: Fully implemented | *Hydra*: ~F8 F8 L j~ (Links & upkeep submenu) | *Module*: ~linking/org-scribe-plot-links.el~

** Character Timeline Generation

Generates a dynamic table showing which characters appear in which scenes, with distinction between PoV characters (◆) and other appearances (●). The dynamic block ~#+BEGIN: character-timeline~ scans all scenes (level-3 headings) in the manuscript, extracts ~:PoV:~ and ~:Characters:~ properties, collects unique characters, and builds a presence matrix. PoV takes precedence (a character won't show both ◆ and ● in the same scene). Update the table by pressing ~C-c C-c~ on the block. Useful for checking character coverage and PoV balance.

*Status*: Fully implemented | *Hydra*: Not in menu (dynamic block) | *Module*: ~linking/org-scribe-character-links.el~

** Plot Thread Timeline Generation

Generates a dynamic table showing which plot threads appear in which scenes using the symbol ● for presence. The dynamic block ~#+BEGIN: plot-thread-timeline~ scans all scenes for ~:Plot:~ properties, collects unique plot threads, and creates a visual timeline matrix. Each plot thread gets a column, each scene gets a row, and ● marks where they intersect. Update with ~C-c C-c~. This helps identify plot gaps (threads that disappear for many scenes), plot convergence (multiple threads in one scene), and overall plot pacing.

*Status*: Fully implemented | *Hydra*: Not in menu (dynamic block — insert ~#+BEGIN: plot-thread-timeline~ manually and press ~C-c C-c~) | *Module*: ~linking/org-scribe-plot-links.el~

** Plot Thread Health Report (~org-scribe-plot-thread-report~)

Analyzes all plot threads in the manuscript and generates a health report identifying potential problems: threads with low coverage (<30% of scenes), threads with large gaps (>5 scenes without appearance), and threads that only appear once. The report displays in a temporary buffer. This helps writers identify neglected plot threads and pacing issues before they become structural problems.

*Status*: Fully implemented | *Hydra*: ~F8 F8 L t~ (Links & upkeep submenu, "plot report") | *Module*: ~linking/org-scribe-plot-links.el~

** Plot Thread Statistics (~org-scribe-plot-thread-stats~)

Displays quick statistics about plot thread usage in the minibuffer: total number of unique plot threads in the manuscript, total number of scenes with plot thread tags, and per-thread appearance counts sorted by frequency. This provides a quick health check without opening a full report buffer. Useful for getting a snapshot of plot distribution during drafting or revision.

*Status*: Fully implemented | *Hydra*: ~F8 F8 L S~ (Links & upkeep submenu, "plot stats") | *Module*: ~linking/org-scribe-plot-links.el~

** Batch Link Conversion

Provides functions to convert existing plain-text character/location/plot references to ID links in bulk. ~org-scribe-link-scene-characters~ converts the current scene, while ~org-scribe-link-all-scene-characters~ processes the entire manuscript. For each property value, the function looks up the name in the database (characters/locations/plot files), finds the matching ID, and replaces plain text with ID links. Useful when migrating existing projects to the linking system or when writers initially use plain text and want to upgrade to linked references later.

*Status*: Fully implemented | *Hydra*: Not directly bound — superseded by the single ~org-scribe-relink-project~ command (~F8 F8 R~ or ~F8 F8 L R~), which performs this conversion for all three entity types in one pass; call these functions via ~M-x~ if you need to target only one entity type or the current scene | *Module*: All three linking modules

** Setup Wizards

Each linking system (characters, locations, plot threads) includes a one-time setup wizard (~org-scribe-setup-character-links~, ~org-scribe-setup-location-links~, ~org-scribe-setup-plot-thread-links~). The wizard: (1) adds IDs to all existing profiles that lack them, (2) asks if you want to convert existing scene properties to links, and (3) confirms the setup is complete. Running the wizard on an existing project enables all linking features retroactively. Wizards are idempotent - running them multiple times is safe.

*Status*: Fully implemented | *Hydra*: ~F8 F8 L c~, ~F8 F8 L o~, ~F8 F8 L p~ (Links & upkeep submenu) | *Module*: All three linking modules

** Add IDs to Existing Entries

Each linking module provides a function to add unique IDs to profiles that don't have them: ~org-scribe-add-character-ids~, ~org-scribe-add-location-ids~, ~org-scribe-add-plot-thread-ids~. These scan the respective files for headings with identifying properties (~:Role:~ for characters, ~:Type:~ for locations and plots) and add ~:ID:~ properties using org-id-get-create. The functions report how many IDs were added. This is the first step in enabling linking in existing projects that were created before the linking system existed.

*Status*: Fully implemented | *Hydra*: Not directly bound — superseded by ~org-scribe-relink-project~ (~F8 F8 R~), which adds missing IDs across all entity types as part of its single pass; call these functions via ~M-x~ to target only one entity type | *Module*: All three linking modules

** Link Display Name Updating (~org-scribe-relink-project~)

Refreshes the display text of all ID links in scene properties to match current entity names in the database files, adds missing IDs, and links any remaining plain-text property values — all in one registry-driven pass across every entity type. When you rename a character, location, or plot thread in the planning files, the ID links still work (they're ID-based), but the visible display text shows the old name. This function scans every entity type's database file to get current names, then updates ~:PoV:~, ~:Characters:~, ~:Location:~, and ~:Plot:~ properties in all scenes throughout the manuscript in a single pass. Reports the number of scenes updated. This single command replaced the older per-entity add-ids/link/update-names functions as the primary upkeep action.

*Status*: Fully implemented | *Hydra*: ~R~ (Manage section, also ~F8 F8 L R~) | *Module*: ~linking/org-scribe-link-update.el~

** Character Relationship Tracking (~org-scribe-add-relationship~)

** Edit Marker Index (~org-scribe-search-edits~)

** Dictionary Lookup (~org-scribe-dictionary-lookup~)

The definition entry point, dispatching on ~org-scribe-dictionary-backend~ between a local Wikcionario served by kiwix-serve and the online RAE API. Under the default ~'auto~ the local server is used when it answers and the RAE otherwise, so a writer who sets up nothing sees the previous online behaviour. ** Local Wikcionario Backend (~org-scribe-wikcionario-resolve~)

Serves definitions from a Spanish Wiktionary ZIM through a local kiwix-serve. Discovers the served book from the OPDS catalogue (reading the content link, since the catalogue's ~<name>~ omits the flavour suffix and 404s), builds article URLs under ~/content/~, and queries ~/suggest~ for near matches on a miss, filtering out the server's synthetic "containing '...'" entry. Its lookup order deliberately differs from the thesaurus module's: Wikcionario stores an article for *every* inflected form, but they are stubs pointing at the dictionary form, so an inflected word resolves to its lemma's article rather than to its own stub. org-scribe never starts, stops or supervises the server — it probes a URL and names the service when nothing answers.

** Lemmatization (~org-scribe-lemma~ / ~org-scribe-lemmas~)

** Scene Break Filter (~org-scribe--export-replace-scene-breaks~)

Automatically replaces ~SCENE-BREAK~ markers with backend-appropriate scene separators during org export. Writers add ~#+MACRO: scene-break SCENE-BREAK~ to their manuscript, then use ~{{{scene-break}}}~ wherever they want scene breaks. During export, the filter replaces these markers with: ~\n***\n~ for ASCII/Markdown/Man, ~<br><br><br>~ for HTML and EPUB (EPUB derives from the HTML backend), a centered ~***~ paragraph for ODT, ~\vspace~ commands for LaTeX, or custom strings defined in ~org-scribe-scene-break-replacements~. *Status*: Fully implemented | *Hydra*: N/A (automatic on export) | *Module*: ~export/org-scribe-export.el~

** Ignore-Headlines Activation (~org-scribe--export-filter-ignore-headlines~)

Every scene and chapter heading in the shipped manuscript templates carries the ~:ignore:~ tag, intended to drop the heading's title from export while keeping its body — plain Org has no built-in handling for a tag literally named "ignore" (~org-export-exclude-tags~ defaults to ~("noexport")~ only), so this requires the optional ~ox-extra~ package's ~ignore-headlines~ extra (part of ~org-contrib~). ** Project Health Report (~org-scribe-project-health~)

Aggregates project-wide statistics into a single ~*org-scribe-health*~ buffer displayed as an org-mode file with clickable ~[[id:...]]~ links back to individual scenes.  The report is organised into seven sections, plus an optional eighth when the bundled writing planner is active for the project:

1. *Overview* — manuscript filename (linked), total scene count, words written (summed from level-3 ~:WORDCOUNT:~), chapter objectives (summed from level-2 ~:WORD-OBJECTIVE:~), and progress percentage.  Using separate levels for actual vs. target avoids the double-counting that would occur if both chapter and scene objectives were totalled together.  A ~Spelling dictionary~ line appears here only when the project's ~.dir-locals.el~ is missing or names a dictionary that disagrees with the project language — drift that is otherwise invisible until a spell check argues with the prose; ~M-x org-scribe-update-dir-locals~ fixes it.

2. *Writing Plan* (optional) — plan title, target word count, current word count and percentage, daily target, end date, and on-track/behind status.  Shown only when a plan is loaded for the project and the project has not opted out of the planner; otherwise a creation/load hint is shown instead, and the section is omitted entirely for a project that declined the planner.

3. *Scenes by Status* — a count of scenes grouped by their org TODO keyword (TODO, DONE, or any custom keyword).  Shows at a glance how much of the draft is complete.

4. *Per-PoV Word Share* — scenes and words grouped by resolved PoV character name, with each PoV's percentage of the manuscript's total words.  Scenes with no PoV set are grouped under a "(no PoV)" row, doubling as a missing-property signal.

5. *Chapter Length Spread* — per-chapter word totals plus a summary line of minimum, maximum, mean, and median chapter length, with outlier chapters (roughly 2x the mean or under half of it) flagged for attention.

6. *Missing Scene Properties* — three subsections listing scenes that lack a ~:PoV:~, ~:Plot:~, or ~:Location:~ value respectively.  Each entry is an ~[[id:...][Scene Heading]]~ link followed by the parent chapter name.

7. *Orphaned Entities* — characters and locations defined in their database files whose IDs do not appear in any scene property.  An entity is considered orphaned if its org ID is absent from every ~:PoV:~, ~:Characters:~, ~:Location:~, and ~:Plot:~ property across all scenes.  Orphaned entities represent planning work not yet woven into the manuscript.

8. *Open TODO Scenes* — a full list of scenes whose TODO state is not DONE, with the state keyword in square brackets and a clickable scene link.

The function requires a novel project with a detectable manuscript file (novel.org / novela.org) and gracefully handles missing character or location database files.  Orphan detection is skipped for entity types whose linking module is not loaded.

*Status*: Fully implemented | *Hydra*: ~H~ (Manage section, visible in hint) | *Module*: ~reporting/org-scribe-health.el~

** Template Directory (~org-scribe-template-directory~)

Points to the directory containing project templates (novel-en/, novel-es/, short-story-en/, short-story-es/). Defaults to the package's bundled templates but can be customized to point to user templates. This allows writers to maintain custom project structures while still using the package's project creation functions. Templates are processed recursively with variable substitution for ${TITLE}, ${AUTHOR}, and ${DATE}.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~templates/org-scribe-project.el~

** Spelling Dictionaries (~org-scribe-ispell-dictionaries~)

Maps a project language to the ispell dictionary name recorded in that project's ~.dir-locals.el~ (default: ~'((en . "en_US") (es . "es_ES"))~). Set a regional variant — ~en_GB~, ~es_MX~, ~es_AR~ — to have new projects use it; run ~M-x org-scribe-update-dir-locals~ inside an existing project to apply a change there. The key is the project's own language, read from ~.org-scribe-project~, not the global ~org-scribe-template-language~ default, so a Spanish project keeps its Spanish dictionary whatever your default for new projects is. A language with no entry, or an entry of ~nil~, writes no dictionary rather than guessing one. A companion boolean, ~org-scribe-write-dir-locals~ (default ~t~), turns the whole mechanism off for writers who manage directory-local variables themselves; an existing ~.dir-locals.el~ is never overwritten by project creation either way.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

Specifies where writing exercise files will be created (default: ~~/writing/exercises~). This directory is used by functions that generate writing prompts or exercises. Writers who maintain separate directories for exercises vs. actual projects can point this elsewhere to keep exercises organized separately from main work. A sibling variable, ~org-scribe-projects-directory~ (default ~~/writing/~), is the base directory offered when creating a new novel or short story project.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

Narrower widths (60-80) are often preferred for drafting to reduce eye movement and create a paper-like feel. Wider settings (85-100) suit editing mode where seeing more context helps. The percent values determine side panel widths as fractions of frame width, while fill-column-width sets the visual line wrapping in the center panel. *Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

The default key ~t~ provides fallback for unspecified backends.

** Synonym Window Width

~org-scribe-sinonimo-window-width~ (default: 80) controls the width of the side window displaying synonym results, offline or online. Narrower values (60-70) work well on smaller screens or when working in split windows. Wider values (90-100) provide more space for longer synonym lists and reduce line wrapping. *Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Thesaurus Backend (~org-scribe-thesaurus-backend~)

Selects where ~org-scribe-sinonimo~ gets its synonyms: ~'mythes~ reads only the offline MyThes data, ~'wordreference~ only the online page, and ~'auto~ (the default) tries offline first and falls back to the web — both when no data is installed and when a particular word has no local entry. The default is chosen so that writers who install nothing keep the previous behaviour exactly, while those who run ~apt install mythes-es~ get instant offline lookups without touching their configuration. Setting ~'mythes~ is useful on a metered connection, or to see honestly what the local data covers instead of having gaps papered over by a web request.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Thesaurus Data Location (~org-scribe-mythes-directory~ / ~org-scribe-mythes-language~)

~org-scribe-mythes-directory~ (default: ~/usr/share/mythes/~) is where the ~th_LANG_v2.dat~ / ~.idx~ pairs live, and ~org-scribe-mythes-language~ (default: ~es_ES~) selects which one to read. Neither normally needs setting — the defaults match where Debian, Ubuntu, Fedora and Arch install the data. Change the directory on systems that put it elsewhere (macOS, or a manual download), and the language when writing in something other than Spanish. A language with no exact match falls back to another variant of the same base language, so ~es_MX~ resolves even when only ~es_ES~ is installed. ~(org-scribe-mythes-files)~ reports what was found.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Dictionary Backend (~org-scribe-dictionary-backend~)

Selects where definitions come from: ~'wikcionario~ reads only a local kiwix-serve, ~'rae-api~ only the online service, and ~'auto~ (the default) uses the local server when it answers. Set ~'wikcionario~ to guarantee no network traffic, which also makes coverage gaps in the local ZIM visible instead of being papered over by an online lookup.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Local Dictionary Server (~org-scribe-wikcionario-url~ / ~-book~ / ~-timeout~)

~org-scribe-wikcionario-url~ (default ~http://localhost:8080~) is where kiwix-serve is listening; ~org-scribe-wikcionario-book~ (default nil) names the ZIM, and nil means "ask the server"; ~org-scribe-wikcionario-timeout~ (default 3 seconds) bounds the availability probe, which is paid only once per session. Note the book name used in URLs carries the flavour suffix (~wiktionary_es_all_nopic~) and differs from the name shown in the OPDS catalogue, which is why auto-discovery is the default.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Lemmatization Dictionary (~org-scribe-lemma-dictionary~)

Names the hunspell dictionary used to reduce inflected words to their dictionary form. When nil (the default) it follows ~org-scribe-mythes-language~, so one setting drives both the thesaurus and the morphology. Set it explicitly only when the two should differ, or when hunspell names its dictionary differently from the thesaurus. *Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

When nil, functions will error if directories don't exist, giving writers full control over project structure. When t (default), convenience is prioritized - directories are created as needed.

Headings tagged with these values (and their content) won't be counted. Useful for marking notes, meta-commentary, or cut scenes that are kept for reference but shouldn't contribute to word count targets. ** Column View Link Stripping

~org-scribe-column-view-strip-links~ (default: t) controls whether ID links are displayed as clean text in org column view. When t, ~[[id:abc][Name]]~ displays as "Name". When nil, full link syntax is shown. Disabling might be useful for debugging link structure or when working on the linking system itself, but most writers will want the clean display enabled.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~linking/org-scribe-column-view.el~

** Edit Note Marker (~org-scribe-edit-string~)

Defines the regexp pattern used by ~org-scribe-search-edits-rgrep~, the plain-text fallback search, to find inline edit notes and revision markers throughout the manuscript. The structured index (~org-scribe-search-edits~) does not use this regexp: it parses the marker grammar directly so it can tell ~*EDIT*~ from ~*NOTE*~ and read categories. Default value is ~"\*EDIT\*\\|\*NOTE\*"~, matching ~*EDIT*~ or ~*NOTE*~ anywhere in .org files. Writers can customize this to match their personal convention: for example ~"FIXME\\|REVISION\\|TOFIX"~ or any other marker they use to flag places needing attention. The pattern is passed to ~rgrep~, so full regexp syntax is supported. Note that the default deliberately does *not* match ~*SUMMARY*~, a related marker for scenes planned but not yet written: those live under ~TODO~ headings and are found with the TODO search instead, keeping notes about absent prose separate from edits to prose that exists.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~search/org-scribe-search.el~

** Edit Marker Categories (~org-scribe-edit-categories~)

The known categories for ~*EDIT*~ markers, used to group the edit index. Default is ~'("plot" "scene" "character" "prose" "design")~. A localized spelling known to `org-scribe--edit-category-aliases' (currently just Spanish "diseño") canonicalizes to its English key before this check. A marker carries its category before a ~" - "~ separator (~*EDIT*: plot - Alice's motive contradicts chapter 1~); matching is case-insensitive. A marker whose category is absent, empty, or not in this list is grouped under a catch-all ~other~ heading rather than being dropped, so a typo moves a marker but never hides it - and the unrecognized category stays visible in the entry text. ~*NOTE*~ markers have no category at all and are listed in their own section.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Show Empty Edit Categories (~org-scribe-edits-index-show-empty-categories~)

Whether the edit index lists categories that currently have no markers (default: t). When enabled, every category gets a heading even when empty, so the index doubles as a checklist showing at a glance which kinds of problem are outstanding and which are clear. Set to nil for a more compact index that shows only categories with something in them.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Editing Mode Right Panel (~org-scribe-editing-right-panel~)

Selects what ~org-scribe-editing-mode~ displays in its right pane. ~notes~ (the default) shows the project notes file, the same file captures write to. ~edits~ shows a live index of inline edit markers that rebuilds itself whenever an Org file in the project is saved - the only value that is a generated buffer rather than a file. ~revision~ shows the project's ~revision.org~. A string is treated as a project-relative file path; a function is called with the manuscript file name and must return the file to display. If a requested file cannot be located, the pane falls back to the project notes file rather than opening nothing. Before org-remark support was removed, this pane always showed a per-manuscript companion file (~novel.org~ → ~novel-notes.org~) that existed only as an annotation sink.

*Status*: Fully implemented | *Type*: defcustom | *Module*: ~core/org-scribe-config.el~

** Bundled Writing Planner (~org-scribe-planner~)

A complete goal-oriented writing planner bundled directly inside ~org-scribe~ at ~planning/org-scribe-planner.el~. No separate installation is required. All public commands carry ~;;;###autoload~ cookies, so they are available as soon as the package is installed without any extra ~require~ in the user's init file. When first invoked, the planner loads on demand and wires itself into org-scribe automatically.

Features provided: (1) auto-load the project's plan file when any project file is opened; (2) push live word counts to the plan after running ~org-scribe-ews-org-count-words~; (3) wire the planner's word count function to read ~WORDCOUNT~ properties from the manuscript; (4) set the planner's project-root function so file pickers start at the current project root; (5) offer plan creation after ~org-scribe-create-novel-project~ / ~org-scribe-create-short-story-project~; (6) add a planner sub-hydra accessible via ~W~ in the main Hydra menu; (7) show today's target/actual in the mode line as ~[W:actual/target]~.

Every one of these integration features is additionally gated *per project*: a project only sees the planner after explicitly opting in via a ~# Planner: yes~/~# Planner: no~ line in ~.org-scribe-project~ (read by ~org-scribe-planner-gate~ in ~core/org-scribe-core.el~). ~nil~ (undecided, the state of a project created before this gate existed) preserves the old always-on behavior; only an explicit ~no~ turns features off. Toggle per project with ~org-scribe-planner-enable-for-project~/~org-scribe-planner-disable-for-project~ (hydra keys ~F8 F8 W E~/~F8 F8 W X~).

Integration features are on by default. To opt out globally, set any of the following variables *before* the planner first loads (e.g. in ~early-init.el~):

#+BEGIN_SRC emacs-lisp
(setq org-scribe-planner-auto-load-plan nil)
(setq org-scribe-planner-auto-push-wordcount nil)
(setq org-scribe-planner-auto-track-daily nil)
(setq org-scribe-planner-offer-plan-on-create nil)
(setq org-scribe-planner-show-mode-line nil)
(setq org-scribe-auto-wordcount nil)   ; keep nil (default) to disable save-triggered full count
#+END_SRC

*Status*: Fully implemented | *Hydra*: ~W~ sub-menu (shown in the Manage section of the main hint) | *Module*: ~planning/org-scribe-planner.el~

** Unified Plan Entry Point (~org-scribe-plan~)

A single autoloaded command that dispatches based on project state: shows the plan calendar if a plan is already active; loads the plan file silently and shows the calendar if a valid plan file exists for the current project but is not yet loaded; offers to create a plan if none exists; falls back to ~org-scribe-planner-show-current-plan~ when not inside an org-scribe project. Accessible via ~F8 F8 W p~.

*Status*: Fully implemented | *Hydra*: ~W p~ | *Module*: ~planning/org-scribe-planner.el~

** Plan File Auto-Discovery

When any project file is opened, the planner locates the plan file using a four-step search: (0) path cached in ~.org-scribe-project~ as a ~# Plan:~ line — written automatically after the first load, making subsequent lookups instant; (1) ~<root>/plan.org~; (2) ~<root>/<project-title>-plan.org~; (3) any ~.org~ file in the root containing a ~TOTAL_WORDS~ property. Once found via steps 1-3, the path is persisted back to ~.org-scribe-project~ so future lookups use step 0.

*Status*: Fully implemented | *Hydra*: N/A (automatic) | *Module*: ~planning/org-scribe-planner.el~

Progress visualisations loaded on demand from ~planning/org-scribe-planner-dashboards.el~. Provides progress charts, burndown graphs (ASCII, SVG, gnuplot), velocity analysis, cumulative progress, performance analytics, multi-metric dashboards, and heatmaps.
