* Welcome to Lesson 16!

You know how to count words, track progress tables, and log your daily sessions. But do you ever wish Emacs could tell you /how many words you need to write today/ to finish your manuscript on time? That's exactly what this lesson is about.

~org-scribe-planner~ is a planning engine bundled directly inside ~org-scribe~. It handles goal-oriented writing plans: target dates, milestones, daily targets, and progress dashboards. Because it ships with the package, there is nothing extra to install and no integration glue to load — everything wires up automatically the first time you invoke a planner command.

By the end of this lesson, you'll have:
- Created a writing plan for your project from inside Emacs
- Seen your live word count pushed to the plan automatically
- Understood the full planner submenu (~W~) in the Hydra
- Learned how to disable individual features you don't want

*Estimated time*: 20-30 minutes

*Note*: This lesson covers an *optional module*. You can skip it if you prefer to track goals manually.

* Before You Begin

** What You Need

✓ ~org-scribe~ installed and working (you've completed Lessons 1-3)
✓ A project with at least a few scenes and word count properties

That's it. ~org-scribe-planner~ is bundled inside ~org-scribe~ and loads on demand the first time you run any planner command — no separate installation, no ~require~ call in your init file.

** If You Previously Used org-scribe-planner-integration

If your init file contains:

#+BEGIN_SRC emacs-lisp
(with-eval-after-load 'org-scribe-planner
  (require 'org-scribe-planner-integration))
#+END_SRC

remove that block. The integration features are now built directly into the planner module, and the ~org-scribe-planner-integration~ compatibility shim has been deleted from the package — that ~require~ will now signal a file-missing error instead of loading a no-op.

* What Does the Integration Do?

Here is an overview of everything the planner provides out of the box. Each feature is independent and can be disabled individually (see [[*Disabling Individual Features][Disabling Individual Features]] at the end of this lesson).

| Feature                      | What happens automatically                                 |
|------------------------------+------------------------------------------------------------|
| Auto-load plan               | Plan file loads when you open any project file             |
| Word count bridge            | Plan reads word counts directly from your manuscript       |
| Auto-update after counting   | ~F8 F8 a~ pushes new total to the plan silently              |
| Auto-update on save          | Saving the manuscript updates all counts and the plan      |
| Project-aware file picker    | Load-plan dialog opens at your project root                |
| Plan creation on new project | Offered when you run ~org-scribe-create-novel-project~       |
| Planner Hydra submenu (~W~)    | Full planner menu accessible from the main Hydra           |
| Mode-line status             | Today's target/actual shown as ~[W:actual/target]~           |
| ~org-scribe-plan~ entry point  | Single command that dispatches based on current plan state |

* Step 1: Create Your Writing Plan

Let's create a plan for an existing project.

** Open Your Project

Open any file inside your org-scribe project (your ~novel.org~, a scene file, etc.).

** Open the Planner Submenu

Press ~F8 F8~ to open the Hydra menu. Press ~W~ to open the planner submenu:

#+BEGIN_EXAMPLE
  org-scribe-planner
  ──────────────────────────────────────────────────
  p: Open project plan (load or create)
  n: New plan
  o: Onboard existing project
  l: Load plan
  u: Sync word count (from manuscript)
  d: Add session note
  r: Recalculate plan
  a: Adjust remaining days (keep end date)
  e: Adjust end date (keep daily words)
  c: Check progress (adjust if ahead/behind)
  m: Milestones
  w: Weekly summary
  M: Month grid
  D: Dashboards menu
  E: Enable for project
  X: Disable for project
  q: Back to main menu
#+END_EXAMPLE

*Before you get here*: this submenu is only reachable once the planner is *enabled for the current project*. A project's opt-in state lives in a ~# Planner: yes~/~# Planner: no~ line in ~.org-scribe-project~ (undecided/~nil~ by default, which behaves like "yes" for backward compatibility with projects created before this gate existed). If a project has explicitly opted out, pressing ~W~ offers to re-enable it instead of showing this submenu. Toggle it explicitly any time with ~E~ (enable) / ~X~ (disable) once you're in the submenu, or via ~M-x org-scribe-planner-enable-for-project~ / ~M-x org-scribe-planner-disable-for-project~.

** The ~p~ Key — Your Main Entry Point

Press ~p~ (Open project plan) at any time. It does the right thing based on context:

- *Plan already active* → shows the plan calendar immediately
- *Plan file exists but not loaded* → loads it silently, then shows the calendar
- *No plan file found* → asks "No writing plan found for this project. Create one?"
- *Not in an org-scribe project* → falls back to standard load-or-show flow

This means ~F8 F8 W p~ is the one command you need to remember.

** Create a New Plan

If no plan exists, press ~p~ and answer ~yes~, or press ~n~ directly (New plan).

Inside a project, the planner pre-fills defaults from your project metadata — no hunting for paths. It will prompt you for:

1. *Plan file location* — defaults to ~plan.org~ in your project root. Accept or type a custom name.
2. *Total word count target* — e.g. ~80000~ for an 80,000-word novel.
3. *Target completion date* — e.g. ~2026-12-31~.
4. *Daily writing days* — which days of the week you plan to write (e.g. Mon–Fri).

The planner creates ~plan.org~ in your project root and calculates your required daily word count automatically.

*Note*: New projects do *not* ship with a ~plan.org~ placeholder — the file (and the ~# Planner: yes~ opt-in marker) only come into existence once you explicitly create a plan, either by accepting the offer shown right after ~org-scribe-create-novel-project~/~org-scribe-create-short-story-project~ (see below), or later via ~M-x org-scribe-plan~ or ~F8 F8 W p~.

** What the Plan File Looks Like

Open ~plan.org~ to see it:

#+BEGIN_EXAMPLE
,* My Novel — Writing Plan
:PROPERTIES:
:TOTAL_WORDS: 80000
:CURRENT_WORDS: 12450
:TARGET_DATE: 2026-12-31
:DAILY_WORDS: 650
:END:
...
#+END_EXAMPLE

The key properties:
- ~TOTAL_WORDS~ — your total manuscript target
- ~CURRENT_WORDS~ — the latest word count (updated automatically)
- ~TARGET_DATE~ — your finish-by date
- ~DAILY_WORDS~ — how many words/day you need to stay on track

* Step 2: Watch Word Counts Sync Automatically

This is where the integration really shines.

** Update Your Manuscript Word Counts

Go to your manuscript (~novel.org~) and run the word count command:

1. Press ~F8 F8 a~ (Update all word count properties)
2. Watch the ~:WORDCOUNT:~ properties update on each heading

** Check the Plan

This sync is completely silent - ~F8 F8 a~ (~org-scribe-ews-org-count-words~) calls ~org-scribe-planner-record-total~ under the hood, which writes today's cumulative total into ~plan.org~ and saves it, but prints *no* minibuffer message and doesn't reopen the calendar. Don't expect to see anything after step 2.

The planner automatically:
1. Summed all ~WORDCOUNT~ properties across your manuscript
2. Wrote the new total to ~plan.org~
3. Saved the plan silently

No extra steps needed for the sync itself. If you want visible confirmation, press ~F8 F8 W u~ (Sync word count / ~org-scribe-planner-update-progress~) instead - unlike the automatic push after ~F8 F8 a~, this command also re-reads the manuscript total, reopens the calendar, and prints a progress line in the minibuffer:

#+BEGIN_EXAMPLE
Progress: 12847/80000 words (16.1%) | Ahead: +120 words
#+END_EXAMPLE

Every time you run ~F8 F8 a~, your plan stays in sync in the background - you just won't see it happen.

** Optional: Automatic Update on Every Save

If you prefer to have word counts and plan sync happen automatically on every
save, add this to your Emacs init file:

#+BEGIN_SRC emacs-lisp
(setq org-scribe-auto-wordcount t)
#+END_SRC

With this enabled, saving ~novel.org~ (or ~novela.org~) runs the full word
count update and syncs the plan silently — no extra key needed.  The trade-off
is a slightly slower save (the word count runs on every heading in the buffer).
Requires ~org-context-extended~; if that package is absent the setting is
ignored.

** Check the Mode Line

Look at the right end of your mode line. You should see something like:

#+BEGIN_EXAMPLE
[W:450/650]
#+END_EXAMPLE

This means:
- ~450~ — words written today (from your daily log entry)
- ~650~ — today's target to stay on track

Green days are satisfying. Make it a habit!

* Step 3: View Your Plan Calendar

Press ~F8 F8 W p~ (Open project plan).

The planner opens a visual calendar showing:
- Each writing day with its target word count
- Actual words written per day (once you log them)
- Color indicators for ahead / on track / behind
- Milestone markers at key word count thresholds

This gives you an at-a-glance picture of your entire project arc.

* Step 4: Log Your Daily Session

If auto-tracking is on (the default — see ~org-scribe-planner-auto-track-daily~), running a word count after writing already updates today's entry for you; you don't need to do anything else. To add a note about the session, or to record an entry manually:

Press ~F8 F8 W d~ (~org-scribe-planner-add-session-note~).

The planner pre-fills today's cumulative word total from the manuscript and prompts you for a session note (what you worked on). Confirming records the entry and the mode line updates immediately. Remember that ~DAILY_WORD_COUNTS~ entries store the manuscript's *cumulative* total as of that date, not that day's delta — the delta shown in the calendar/mode line is derived automatically by subtracting the previous entry.

*Tip*: Combine this with your existing daily writing log (from Lesson 3). The plan calendar gives you the goal-oriented view; your manuscript's progress table gives you the structural view. Both are valuable!

* Step 5: Keep the Plan Healthy

As you write, things change — you get ahead, fall behind, or adjust your target. Here are the tools for that.

** Recalculate the Plan

Press ~F8 F8 W r~ (Recalculate), or ~r~ in the plan calendar.

Use it when the plan itself changes. It asks /What changed?/:

- *Total words*, *Daily words* or *Days available* — then asks which of the other two to keep. A new total can keep the writing days (the daily target follows) or the daily target (the end date moves).
- *Two values* — set two of total, daily words and days; the third is calculated.
- *Start date* — move the plan earlier or later. It keeps the same number of writing days, so the end date moves too. Spare days and day goals from today on can stay on their dates (the default) or move with the start; past ones never move, and neither do the words you've written. Before applying, it warns you about written words that would fall outside the plan and past days that would join it. A plan already under way is recalculated so its remaining days cover the words left.
- *Writing pattern* — how the words are spread: steady, /valley/ (start high, ease in the middle, finish high), /mountain/ (start easy, peak in the middle), /rising/, /declining/ or /random/, each mild, moderate or extreme. Only the days still to come change shape.
- *Weekends* — the same goal as other days, a goal of their own (say, more words on Saturdays and Sundays), or no writing; and which days count as the weekend.
- *Day goal* — a goal for one date: more words on a free day, fewer on a busy one, 0 to make it a rest day. Not for past days, spare days or weekends off.
- *Spare days* (add, remove, clear) — then asks how the plan absorbs them: keep the end date (the daily target changes), move the end date (keep the daily target), or keep both (the total changes). Weekend and day-goal changes ask the same.

Every option shows its outcome before you choose — /ends 2026-12-01, 1000 words/day, total 30000 words/ — and the first one is the default. Past days keep their goals whatever you choose. If you have synced the plan to the agenda, its entries are regenerated.

To recompute targets from your progress instead, use /Adjust Remaining Days/ or /Adjust the End Date/ below.

** Adjust Remaining Days

Press ~F8 F8 W a~ (Adjust remaining days).

Use this when your schedule changes — vacation, deadline moved, days off. The planner redistributes the remaining word count across the new schedule.

The end date stays where it is: only the daily target changes. Past days keep the goals they had — only the days from today on (from tomorrow, if you have already written today) share the words you actually have left. Afterwards the plan counts you as on track: it measures from what you had written when you recalculated.

Before applying anything it shows the change — /From 2026-11-11: 25000 words left over 20 writing days. Daily target 1000 → 1250 words (+250, +25.0%)/ — and asks.

** Adjust the End Date

Press ~F8 F8 W e~ (Adjust end date), or ~e~ in the plan calendar.

The opposite trade: keep your daily target and move the end date so the words left fit. Ahead of schedule, you finish early; behind, the deadline is extended. Spare days are skipped, and if you have already written today, the count starts tomorrow. It shows the new end date (/End date 2026-11-30 → 2026-12-05: extended by 5 days/) and asks before applying it.

** Check Progress

Press ~F8 F8 W c~ (Check progress), or ~c~ in the plan calendar.

It tells you where the plan stands — /On track/, or /Behind: -500 words (-5.0%, -0.5 writing days)/ — counting your goals through yesterday: today's goal isn't due until the day is over, but the words you've already written today count. The writing days are measured along your own schedule, day by day.

When you are ahead or behind it offers the two adjustments above, each with its outcome: ahead, /reduce the daily target/ or /finish early/; behind, /increase the daily target/ or /extend the deadline/. Keeping the plan as it is stays the default.

The same status line appears in the plan calendar's summary and after every word-count sync.

** Week by Week, Month by Month

Press ~F8 F8 W w~ (or ~w~ in the plan calendar) for the /weekly summary/: one row per calendar week with the days written out of the writing days, rest days, the daily goal, the week's goal, the words written (✓ the goal met, ~ part of it, ✗ none) and their share of the goal, and where the manuscript should stand against where it does. The current week is measured through yesterday.

Press ~F8 F8 W M~ (or ~M~) for the /month grid/: one calendar per month, each day with its goal, its result (✓ ~ ✗) and the share of the whole goal written by then. Today is in brackets; while today is under way it shows the words so far.

Weeks start on Monday. To start them on Sunday — in the plan calendar, the weekly summary, the month grid and the heatmap:

#+begin_src emacs-lisp
(setq org-scribe-planner-week-start-day 0)
#+end_src

** How the Numbers Are Counted

The dashboards measure your writing against each day's own goal, over your /writing days so far/: every day up to yesterday that isn't a rest day, plus any day you wrote on.

- A day you missed counts, with 0 words: your average pace and your weekday averages include it. Rest days — spare days, weekends off, a day goal of 0 — don't.
- A day is /met/ at its goal, /partial/ from 75%, /missed/ below that or with nothing — and also when the manuscript ended the day shorter than it started (you cut more than you wrote). The heatmap, the achievement rate and the calendar's ✓ ~ ✗ marks all use this.
- Best and worst day only look at days you wrote on.
- The estimated finish spends your pace on each coming writing day, skipping rest days — your average pace, and your last week's.

** Starting from a Preset

A new plan first asks /Start from:/ — a preset, or from scratch. In a novel project the default is /Novel draft/ (80,000 words in 60 days); in a short-story project, /Short story/ (5,000 words in a week). There are also /NaNoWriMo/, /Novella/ and two daily habits (1,000 and 500 words a day).

A preset only fills in the answers: the total and the days (or words per day) are asked with its values ready, so ~RET~ keeps them and any number replaces them. Its suggested pattern and weekend setting are offered too — say yes or no to each.

To change the presets, customize ~org-scribe-planner-presets~.

*Defaults for plans from scratch.* If you always plan the same way, set it once; a new plan made from scratch then offers it:

#+begin_src emacs-lisp
(setq org-scribe-planner-default-pattern 'valley           ; or mountain, rising, …
      org-scribe-planner-default-pattern-intensity 'mild   ; mild, moderate, extreme
      org-scribe-planner-default-weekend-mode 'rest        ; same, different, rest
      org-scribe-planner-default-weekend-days '(6 0)       ; Saturday and Sunday
      org-scribe-planner-default-weekend-daily nil)        ; nil: 1.5 × the daily target
#+end_src

** Starting Mid-Draft

Press ~F8 F8 W o~ (Onboard existing project) when the manuscript already has words.

The planner reads the manuscript's word count and stores it as the plan's /pre-existing words/. The plan starts today (you can pick another date), and the daily target covers only the words left: a 30,000-word goal with 20,000 already written, over 10 days, is 1,000 words a day.

Pre-existing words count toward the goal and the completion percentage, but never as one day's writing. Your first sync records only the words you wrote that day, so your pace, streaks and best day reflect the plan's writing alone.

A plan created with ~F8 F8 W n~ inside a project takes the manuscript's count the same way.

** Words Written Elsewhere

The planner counts your manuscript on every sync. Words that count toward your goal but aren't in it — an earlier draft in another file, pages in a notebook, text you haven't pasted in yet — need to be told apart, or every sync would miss them and the plan would look behind by exactly that many.

When you onboard a manuscript or create a plan in a project, the planner shows the manuscript's count and then asks for /words written elsewhere/:

- *Type a number* — fixed until you change it.
- *Count files* — point to one or more files; Org files are counted like the manuscript (no headings, drawers or comments), others by words. For each file choose: /on every sync/ (a draft you keep adding to; the default for files inside the project) or /once/ (its count now; the default for files elsewhere).

Both add up, and the plan's written total is always /the manuscript + these/.

To change them later — or to fix a plan made before this existed — use ~F8 F8 W r~ → /Words outside the manuscript/: set the typed number, add a file or stop counting one. Then say what those words are:

- /Among the starting words already declared/ — you told the plan about them when you created it, but they weren't recorded: the record is corrected, and the plan stops looking behind.
- /New to the plan, written before it/ — the starting words rise with them, so your progress doesn't change.

Both are previewed. If a sync ever finds fewer words than the plan started with, the planner suggests this option.

** Update Progress Manually

Press ~F8 F8 W u~ (Update progress).

This reads the current total directly from your manuscript (same as the automatic sync after ~F8 F8 a~), but you can trigger it any time without re-running the full word count command.

** Milestones

Press ~F8 F8 W m~ (Milestones).

Milestones are named word count checkpoints — "Act I complete", "Halfway!", "First draft done". The planner lets you define them and marks them on the calendar.

** Dashboards

Press ~F8 F8 W D~ (Dashboards menu).

The planner provides various progress dashboards: simple totals, daily averages, streak tracking, burndown charts, velocity trends, and projected completion dates based on your recent pace.

* Step 6: Plan Creation on New Projects

Whenever you create a new project with ~M-x org-scribe-create-novel-project~ or ~M-x org-scribe-create-short-story-project~, the planner will offer:

#+BEGIN_EXAMPLE
Create a writing plan for "My New Novel" with org-scribe-planner? (yes or no)
#+END_EXAMPLE

Answer ~yes~ and the planner opens immediately, walking you through creating the plan (and writing ~# Planner: yes~ to ~.org-scribe-project~). Answer ~no~ and it writes ~# Planner: no~ instead — the project won't be asked again until you run ~org-scribe-planner-enable-for-project~ or ~M-x org-scribe-plan~ yourself. Either way, there is no ~plan.org~ placeholder shipped in the template; the file only appears once you actually create a plan.

* How Auto-Loading Works

When you open any file inside an org-scribe project, the planner looks for a plan file automatically. It checks in this order:

0. *Cached path* — if ~.org-scribe-project~ contains a ~# Plan:~ line written during a previous load, that path is used directly (fastest path, skips the scan entirely)
1. ~<project-root>/plan.org~
2. ~<project-root>/<project-title>-plan.org~ (title read from ~.org-scribe-project~)
3. Any ~.org~ file in the project root that contains a ~TOTAL_WORDS~ property

Once a plan file is found via steps 1-3, the path is written back to ~.org-scribe-project~ so future lookups use step 0.

If a matching file is found, the plan loads silently and you see:

#+BEGIN_EXAMPLE
org-scribe-planner: loaded plan "My Novel".
#+END_EXAMPLE

If no plan file exists yet, nothing happens — no error, no interruption.

* Disabling Individual Features

Every integration feature can be turned off independently. Set these variables *before* the planner first loads — the safest place is ~early-init.el~ or anywhere in your init file before the first planner command runs:

** Disable Auto-Loading Plans

#+BEGIN_SRC emacs-lisp
;; Don't load the plan automatically when opening a project file
(setq org-scribe-planner-auto-load-plan nil)
#+END_SRC

** Disable Automatic Word Count Push

#+BEGIN_SRC emacs-lisp
;; Don't push word counts to the plan after F8 F8 a
(setq org-scribe-planner-auto-push-wordcount nil)
#+END_SRC

** Disable Plan Creation Offer on New Projects

#+BEGIN_SRC emacs-lisp
;; Don't offer to create a plan after creating a novel/short story project
(setq org-scribe-planner-offer-plan-on-create nil)
#+END_SRC

** Disable Mode-Line Status

#+BEGIN_SRC emacs-lisp
;; Don't show [W:actual/target] in the mode line
(setq org-scribe-planner-show-mode-line nil)
#+END_SRC

** Disable Auto Word Count on Save

#+BEGIN_SRC emacs-lisp
;; Keep saves fast — don't run the full word count on every save
;; (This is the default; only set it if you previously enabled it.)
(setq org-scribe-auto-wordcount nil)
#+END_SRC

All settings can be combined in one block:

#+BEGIN_SRC emacs-lisp
;; Opt out of all automatic tracking features
(setq org-scribe-planner-auto-load-plan nil
      org-scribe-planner-auto-push-wordcount nil
      org-scribe-planner-offer-plan-on-create nil
      org-scribe-planner-show-mode-line nil
      org-scribe-auto-wordcount nil)
#+END_SRC

* Practical Exercise

Let's do a complete write-and-track cycle using the planner.

** Exercise: Your First Integrated Session

1. *Open your project* — open ~novel.org~ in your project.
2. *Check auto-load* — after a moment, does the minibuffer show ~org-scribe-planner: loaded plan~? If no plan exists yet, continue to step 3.
3. *Open the planner* — press ~F8 F8 W p~. If no plan exists, answer ~yes~ to create one and follow the prompts.
4. *Write something* — activate writing mode (~F8 F8 m~), write 200 words, exit mode, save (~C-x C-s~).
5. *Update word counts* — press ~F8 F8 a~. This pushes the new total to the plan silently (no minibuffer message).
6. *Check mode line* — is ~[W:actual/target]~ visible? Does the actual number match what you just wrote? (This is the actual confirmation that the sync worked.)
7. *Log the session* — press ~F8 F8 W d~ and enter today's session word count.
8. *View the calendar* — press ~F8 F8 W p~ to see your plan.

Congratulations — you have a fully integrated writing tracking system!

* Common Questions

** "I don't see the planner submenu in the Hydra hint."

The ~W~ key appears in the *Manage* column of the main Hydra hint as ~_W_: Planner…~. If you don't see it, confirm that ~org-scribe-mode~ is active (check the mode line). The planner commands load on first use — press ~F8 F8 W~ once to trigger the load, after which all planner keys are available.

** "Auto-load says 'loaded plan' but I didn't create one yet."

The planner found an existing ~.org~ file in your project root that has a ~TOTAL_WORDS~ property (step 3 of the search order) — perhaps a plan you (or a previous collaborator) created and forgot about. Open it and fill in your targets, or rename/delete it if you don't want to use the planner yet.

** "The mode line shows [W:0/650] even though I wrote today."

If ~org-scribe-planner-auto-track-daily~ and ~org-scribe-planner-auto-push-wordcount~ are both on (the default), running a word count (~F8 F8 a~ or ~F8 F8 w~) should update today's entry automatically. If it still shows 0, run ~F8 F8 W d~ (~org-scribe-planner-add-session-note~) — it pre-fills today's cumulative total from the manuscript and prompts you for a session note; confirming updates the entry. The mode line will update immediately.

** "I want to track words for multiple projects independently."

Each project has its own ~plan.org~ at its root. When you switch between projects (open a file in a different project), the planner detects the new project root and loads that project's plan. The two plans remain separate.

** "Can I use this with a short story project?"

Yes! The planner works identically with short story projects. The plan file goes in the short story's project root (~story.org~'s parent directory).

** "I was using org-scribe-planner as a separate package from Codeberg."

The standalone Codeberg package is superseded by the bundled version. If you still have the standalone package on your load path, the bundled ~planning/org-scribe-planner.el~ takes precedence when loaded through ~org-scribe~. You can safely remove the standalone package from your load path and init file — all functionality is preserved in the bundled version.

* Troubleshooting

** "W in the Hydra does nothing."

- Confirm the planner has been loaded at least once: ~M-: (featurep 'org-scribe-planner) RET~. If it returns ~nil~, trigger a load by running ~M-x org-scribe-plan~.
- Confirm hydra is installed: ~M-: (featurep 'hydra) RET~.

** "Plan doesn't auto-load even though plan.org exists."

- Confirm you're inside an org-scribe project (the directory must have a ~.org-scribe-project~ marker file).
- Confirm ~org-scribe-mode~ is active in the buffer (check mode line for ~Write~).
- Confirm auto-load is enabled: ~M-: org-scribe-planner-auto-load-plan RET~ should return ~t~.
- Try loading manually: ~M-x org-scribe-planner-load-plan~.

** "Word counts don't push to the plan after F8 F8 a."

- A plan must be active. Check: ~M-: org-scribe-planner--current-plan RET~ — should be non-nil.
- Confirm auto-push is enabled: ~M-: org-scribe-planner-auto-push-wordcount RET~ should return ~t~.
- Run ~F8 F8 W u~ (Update progress) manually to test the word count bridge independently.

** "I get an error loading org-scribe-planner-integration."

Your init file still contains ~(require 'org-scribe-planner-integration)~. Remove that line — the file has been deleted, and the integration is built directly into the planner module, so nothing needs to be required for it separately.

** Integration Features Summary

| Feature                   | Enabled by default | Variable to disable / enable                       |

| Auto-load plan            | Yes                | ~(setq org-scribe-planner-auto-load-plan nil)~       |
| Auto-push after ~F8 F8 a~   | Yes                | ~(setq org-scribe-planner-auto-push-wordcount nil)~  |
| Offer plan on new project | Yes                | ~(setq org-scribe-planner-offer-plan-on-create nil)~ |
| Mode-line status          | Yes                | ~(setq org-scribe-planner-show-mode-line nil)~       |
| Auto word count on save   | *No* (opt-in)        | ~(setq org-scribe-auto-wordcount t)~                 |

All planner variables must be set *before* the planner first loads (e.g. in ~early-init.el~).
