* Welcome to Lesson 9!

You've been using writing mode (~F8 F8 m~) throughout the previous lessons, but ~org-scribe~ actually offers *four different modes* for different writing workflows. Each mode transforms your environment in unique ways to support specific tasks.

In this lesson, we'll explore all four modes in detail and learn when to use each one.

By the end of this lesson, you'll have:
- Understood all four writing modes and their purposes
- Learned the specific features each mode provides
- Practiced switching between modes efficiently
- Discovered which mode fits your personal writing style
- Customized mode settings to your preferences

*Estimated time*: 15-20 minutes

* Before You Begin

** What You Need

✓ A writing project open with at least one scene
✓ Some written content (200+ words recommended)
✓ Familiarity with the Hydra menu (~F8 F8~)

** Optional Dependencies

Some modes work better with optional packages:
- *All modes*: ~writeroom-mode~ (required for modes 1-2)
- *Navigate mode*: ~treemacs~ and ~imenu-list~ (recommended)
- *Editing mode*: ~imenu-list~ and ~visual-fill-column~ (recommended)
- *Theming*: ~consult~ and ~fontaine~ (optional but nice)

Don't worry if you don't have all of these - we'll explain which features need what!

* The Four Writing Modes

~org-scribe~ provides four mutually exclusive modes:

** Overview Table

| Mode             | Key | Purpose                   | Best For                    |
|------------------+-----+---------------------------+-----------------------------|
| Distraction-Free | ~m~   | Clean, focused writing    | Daily writing, first drafts |
| Focus Mode       | ~f~   | One section at a time     | Intensive scene work        |
| Navigate Mode    | ~v~   | Navigation + writing      | Complex projects, jumping   |
| Editing Mode     | ~e~   | Three-pane editing layout | Revision, notes integration |

** Mutual Exclusivity

*Important*: Only one mode can be active at a time!

When you activate a mode:
1. Any other active mode automatically deactivates
2. Previous settings are restored before the new mode activates
3. This prevents conflicts and maintains clean state

*What this means*:
- ~F8 F8 m~ when Focus Mode is active → Focus exits, Distraction-Free activates
- ~F8 F8 v~ when Editing Mode is active → Editing exits, Project activates
- Activating the same mode again → Exits that mode (toggle behavior)

** Quick Summary

Before we dive deep, here's the essence of each mode:

1. *Distraction-Free* (~m~): Clean canvas, no distractions, just you and words
2. *Focus* (~f~): Like Distraction-Free, but shows only current section
3. *Project* (~v~): Two navigation panels + writing area (overview + detail)
4. *Editing* (~e~): Three panels - outline + manuscript + notes (serious revision)

* Mode 1: Distraction-Free Writing Mode

** What It Does

Activates: ~F8 F8 m~

*Visual changes*:
- Switches to clean, minimal theme (default: ~poet~)
- Changes font to writing preset (larger, more readable)
- Enables ~writeroom-mode~ (centers text, hides mode line)
- Shows line numbers
- Narrows text width to comfortable reading (default: 80 columns, configurable)

*The result*: A clean, centered, distraction-free writing canvas

** When to Use

Perfect for:
- Daily writing sessions (your default mode)
- First draft writing (no distractions needed)
- Getting into flow state
- Timed writing sprints
- When you want to focus purely on words

*Not ideal for*:
- Navigation between scenes (no outline visible)
- Reference checking (can't see notes)
- Structural editing (need broader view)

** How It Works

1. *Before activation*: Normal Emacs with your usual theme, windows, etc.
2. *Press* ~F8 F8 m~
3. *Screen changes*:
   - Theme switches (dark/complex → light/minimal)
   - Font increases (easier reading)
   - Text centers on screen
   - Mode line simplifies
   - Everything but your text fades away
4. *Write freely!*
5. *Press* ~F8 F8 m~ again to exit
6. *Everything restores*: Theme, font, windows - all back to normal

** Customization Variables

Control how Distraction-Free mode looks:

#+BEGIN_SRC emacs-lisp
;; Theme while writing
(setq org-scribe-env-work-theme 'poet)  ; or modus-operandi, etc.

;; Normal theme (restored when exiting)
(setq org-scribe-env-normal-theme 'ef-deuteranopia-dark)

;; Font preset while writing (requires fontaine)
(setq org-scribe-env-work-font 'writing-big)

;; Normal font preset
(setq org-scribe-env-normal-font 'regular)

;; Text width (columns)
(setq org-scribe-env-work-width 80)  ; narrower = more focused
#+END_SRC

* Mode 2: Focus Mode

** What It Does

Activates: ~F8 F8 f~

*Everything from Distraction-Free mode, PLUS*:
- Narrows buffer to current org section
- Shows *only* the scene/chapter at point
- Everything else disappears temporarily

*The result*: Laser focus on a single section

** When to Use

Perfect for:
- Intensive work on one scene
- Rewriting a difficult section
- When rest of manuscript is distracting
- Final polish on specific scenes
- Getting unstuck on a problem section

*Not ideal for*:
- First drafts (you might want to see context)
- Jumping between scenes (must widen, navigate, narrow again)
- Checking continuity (need to see other scenes)

** The Difference from Distraction-Free

| Aspect       | Distraction-Free      | Focus Mode              |
|--------------+-----------------------+-------------------------|
| *Visibility*   | Entire manuscript     | Current section only    |
| *Scrolling*    | Can scroll anywhere   | Scrolls within section  |
| *Navigation*   | All headings visible  | Only current heading    |
| *Mental Model* | "Work on manuscript"  | "Work on THIS scene"    |
| *When to Exit* | After writing session | After finishing section |

** How It Works

1. *Position cursor* on the scene/chapter you want to focus on
2. *Press* ~F8 F8 f~
3. *Buffer narrows*:
   - Only current subtree visible
   - Everything else hidden (not deleted!)
   - Scrolling limited to visible content
   - Plus all Distraction-Free mode effects
4. *Work on that section*
5. *Press* ~F8 F8 f~ again to exit
6. *Buffer widens*: Full manuscript visible again + normal environment restored

** Practical Workflow

*Scenario*: Scene 3 needs rewriting, but seeing other scenes distracts you.

1. Navigate to Scene 3 heading
2. ~F8 F8 f~ (activate Focus mode)
3. Now you see ONLY Scene 3
4. Rewrite intensively
5. ~F8 F8 f~ (exit)
6. Full manuscript visible again
7. Navigate to Scene 4
8. ~F8 F8 f~ (focus on Scene 4)
9. Repeat...

** Customization

Focus mode uses the same customization as Distraction-Free mode:
- Same theme settings
- Same font settings
- Same width settings

No separate configuration needed!

* Mode 3: Navigate Mode

** What It Does

Activates: ~F8 F8 v~

*Layout changes*:
- Opens ~treemacs~ on the left (project file tree)
- Opens ~imenu-list~ on the right (current file outline)
- Main buffer in center (your manuscript)
- Three-panel layout for navigation + writing

*The result*: Overview of project structure + document outline + writing area

** When to Use

Perfect for:
- Complex projects with many files
- Jumping between planning files and manuscript
- Navigating large manuscripts quickly
- When you need structural overview
- Managing multiple chapters/sections

*Not ideal for*:
- Pure writing (panels are distracting)
- Small screens (too cramped)
- Short stories (unnecessary complexity)

** The Two Navigation Panels

*** Left Panel: Treemacs (Project Files)

*Shows*:
- All files in your project
- Directory structure
- Icons for file types

*Use for*:
- Opening character profiles
- Switching to plot document
- Accessing notes files
- Managing project files

*Actions*:
- Click file to open
- Expand/collapse directories
- See project at a glance

*** Right Panel: Imenu-List (Document Outline)

*Shows*:
- Headings in current file
- Hierarchical structure
- Acts → Chapters → Scenes

*Use for*:
- Jumping to specific scene
- Seeing manuscript structure
- Quick navigation within file

*Actions*:
- Click heading to jump
- See where you are in story
- Navigate large documents

** How It Works

1. *Press* ~F8 F8 v~
2. *Frame splits into three*:
   - Treemacs opens (left)
   - Imenu-list opens (right)
   - Current buffer stays (center)
   - Focus remains in center (ready to write)
3. *Use navigation panels as needed*:
   - Click treemacs to open files
   - Click imenu-list to jump within file
   - Keep working in center panel
4. *Press* ~F8 F8 v~ again to exit
5. *Panels close*: Back to normal single-buffer view

** Workflow Example

*Scenario*: Writing a scene, need to check character details.

1. ~F8 F8 v~ (activate Navigate mode)
2. Left panel (treemacs) → click ~objects/characters.org~
3. Character file opens in center
4. Read character details
5. Left panel → click ~novel.org~
6. Manuscript returns to center
7. Continue writing with fresh details
8. ~F8 F8 v~ (exit) when navigation not needed

** Dependencies

Navigate mode *requires*:
- ~treemacs~ package
- ~imenu-list~ package

If not installed:
- Mode still activates
- Warning messages appear
- Some features won't work

*To install* (if using package.el):
#+BEGIN_SRC emacs-lisp
M-x package-install RET treemacs RET
M-x package-install RET imenu-list RET
#+END_SRC

* Mode 4: Editing Mode

** What It Does

Activates: ~F8 F8 e~

*Advanced three-panel layout*:
- Left: ~imenu-list~ (document outline - 25% width)
- Center: Current manuscript (50% width)
- Right: Companion notes file (25% width)
- Applies editing-optimized theme and fonts
- Centers text with margins

*The result*: Professional editing environment with notes side-by-side

** When to Use

Perfect for:
- Revision sessions (second draft onward)
- Editing with annotations
- Keeping a companion notes file open next to the manuscript
- Comparing manuscript to planning notes
- Serious structural editing

*Not ideal for*:
- First draft writing (too complex)
- Small screens (needs width)
- Quick edits (overkill)
- Daily writing sessions (use Distraction-Free instead)

** The Three Panels Explained

*** Left Panel: Imenu-List (Outline)

*Purpose*: Navigate your manuscript structure

*Shows*:
- All headings in manuscript
- Hierarchical organization

*Use for*:
- Jumping to scenes
- Seeing structure
- Quick navigation

*** Center Panel: Main Buffer (Manuscript)

*Purpose*: Your actual editing area

*Shows*:
- The manuscript you're editing
- Centered with margins for readability

*Use for*:
- Making edits
- Reading scenes
- Main revision work

*** Right Panel: Notes File

*Purpose*: Companion notes for manuscript

*Shows*:
- The project notes file — ~notes/notes.org~ (~notas/notas.org~ in Spanish projects), or ~notes.org~ for short stories
- The same file your captures go to, so notes written here and notes captured with ~F8 F8 n~ land in one place
- Your revision notes, ideas, TODOs

*Use for*:
- Writing editing notes
- Tracking issues to fix
- Recording ideas
- Managing revision checklist

** Notes File Creation

When you activate Editing mode:
1. If the project notes file exists → opens it
2. If it doesn't exist → creates it automatically, with a title and a top-level notes heading

** Showing Something Else in the Right Panel

The right panel is configurable through ~org-scribe-editing-right-panel~:

| Value             | Right panel shows                                       |
|-------------------+---------------------------------------------------------|
| ~notes~ (default) | The project notes file                                  |
| ~revision~        | The project's ~revision.org~                            |
| a string          | A project-relative path, e.g. ~"notes/research.org"~    |
| a function        | Called with the manuscript file name; returns a file    |

#+BEGIN_SRC elisp
;; Show revision.org instead of the notes file
(setq org-scribe-editing-right-panel 'revision)
#+END_SRC

If the requested file cannot be found, the panel falls back to the project notes file rather than opening nothing.

*Note*: this panel used to show a per-manuscript companion file (~novel.org~ → ~novel-notes.org~) that existed to hold org-remark annotations. org-remark support has been removed — use inline ~*EDIT*~ / ~*NOTE*~ markers and ~F8 F8~ then ~6~ instead — so the panel now defaults to the project notes file. Any existing ~novel-notes.org~ in your projects is left untouched; open it normally if it holds content you want.

** How It Works

1. *Open your manuscript* (e.g., ~novel.org~)
2. *Press* ~F8 F8 e~
3. *Frame splits into three*:
   - All other windows close
   - Imenu-list appears (left, 25%)
   - Your manuscript stays (center, 50%)
   - Notes file opens/creates (right, 25%)
4. *Visual profile applies*:
   - Theme changes to editing theme (default: ~leuven~)
   - Font changes to editing preset
   - Text centering with margins
5. *Edit freely*, jump between panels
6. *Press* ~F8 F8 e~ to exit
7. *Previous layout restores*: Windows, theme, font - all back

** Workflow Example

*Scenario*: Revising Chapter 3 with specific notes.

1. Open ~novel.org~
2. ~F8 F8 e~ (activate Editing mode)
3. ~notes/notes.org~ opens automatically (right panel)
4. In notes panel, write:
   #+BEGIN_EXAMPLE
   * Chapter 3 Revision
   ** Scene 1
   - [ ] Fix pacing (too slow)
   - [ ] Add dialogue
   - [ ] Show Alex's reaction
   #+END_EXAMPLE
5. Click "Scene 1" in left panel (imenu-list)
6. Center panel jumps to Scene 1
7. Read scene while referencing notes
8. Make edits in center panel
9. Check off items in right panel (notes)
10. Navigate to next scene via left panel
11. Repeat revision process
12. ~F8 F8 e~ when done - layout closes, work saved

** About the Notes File

Editing mode's right panel is your project's notes file - ~notes/notes.org~
(~notas/notas.org~ in Spanish projects), or ~notes.org~ for short stories.
It is created automatically if it doesn't exist yet. This is the same file
~F8 F8 n~ captures into, so notes typed in the panel and notes captured from
elsewhere all end up in one place.

For notes that belong to a *specific sentence* rather than to the project as
a whole, don't use this panel - write an inline marker in the manuscript
itself and find them later with ~F8 F8~ then ~6~. See lesson 14, "Marker
Convention".

org-scribe does not integrate with ~org-remark~ or any other annotation
package - the right panel is a plain org file opened alongside your
manuscript.

** Customization Variables

#+BEGIN_SRC emacs-lisp

(setq org-scribe-editing-fill-column-width 90)

(setq org-scribe-editing-fontaine-preset 'editing)
#+END_SRC

* Choosing the Right Mode

Here's a decision guide for which mode to use when.

** Decision Tree

#+BEGIN_EXAMPLE
START
  |
  ├─ First draft writing? ──→ YES ──→ Distraction-Free Mode (m)
  │                          NO ↓
  │
  ├─ One scene needs intensive work? ──→ YES ──→ Focus Mode (f)
  │                                     NO ↓
  │
  ├─ Jumping between files often? ──→ YES ──→ Navigate Mode (v)
  │                                  NO ↓
  │
  └─ Serious revision with notes? ──→ YES ──→ Editing Mode (e)
                                      NO ──→ No mode needed!
#+END_EXAMPLE

** By Task Type

| Task                    | Best Mode        | Why                             |
|-------------------------+------------------+---------------------------------|
| Daily writing           | Distraction-Free | Clean, focused, no distractions |
| Rewriting problem scene | Focus            | Laser focus on one section      |
| Research while writing  | Project          | Easy file switching             |
| Second draft revision   | Editing          | Notes + manuscript side-by-side |
| Outlining               | Project          | See structure clearly           |
| Writing sprints         | Distraction-Free | Minimal interface, max focus    |
| Structural editing      | Editing          | Outline + text + notes          |
| Character checking      | Project          | Jump to character files         |
| Final polish            | Focus            | One scene at a time, perfecting |

** By Writer Preference

*** "I like simplicity"
→ Distraction-Free mode for everything
→ Occasionally Focus mode for tough scenes

*** "I need navigation"
→ Navigate mode as default
→ Switch to Distraction-Free when actually writing

*** "I'm a serious editor"
→ Editing mode for all revision work
→ Distraction-Free for new material

*** "I want it all"
→ Learn to switch modes fluidly
→ Use the right tool for each task

** Combining Modes with Workflow

*Morning routine*:
1. ~F8 F8 v~ - Check what needs writing (project overview)
2. Navigate to today's scene
3. ~F8 F8 m~ - Switch to distraction-free
4. Write for 1 hour
5. ~F8 F8 m~ - Exit, check progress

*Revision routine*:
1. ~F8 F8 e~ - Activate editing mode
2. Review notes in right panel
3. Work through revision checklist
4. Make edits in center panel
5. Update notes as you go
6. ~F8 F8 e~ - Exit when done

* Advanced Customization

** Customizing Distraction-Free and Focus Modes

Both modes use the same variables:

#+BEGIN_SRC emacs-lisp
;; In your init.el or .emacs:

;; === THEMES ===
;; Writing mode theme (clean, minimal)
(setq org-scribe-env-work-theme 'poet)
;; Options: poet, modus-operandi, ef-light, leuven

(setq org-scribe-env-normal-theme 'modus-vivendi)
;; Use whatever theme you normally use

;; Writing mode font preset
(setq org-scribe-env-work-font 'writing-big)

;; Normal font preset
(setq org-scribe-env-normal-font 'regular)

;; === TEXT WIDTH ===
;; Writing mode width (columns)
(setq org-scribe-env-work-width 80)
;; 60-70: very narrow, intense focus
;; 80: classic, comfortable
;; 90-100: wider, more context

;; Normal mode width (not used much)

#+END_SRC

* Common Questions

** "Which mode should I use for daily writing?"

*Answer*: Distraction-Free mode (~F8 F8 m~)

It's the most popular for daily writing because:
- Clean, minimal interface
- Easy to activate/deactivate
- No navigation panels to distract
- Full manuscript visible (can scroll to reference earlier scenes)
- Fast toggle (same key enters and exits)

** "Can I use writing modes outside of org-scribe projects?"

*Answer*: Technically yes, but some features require project structure.

- Distraction-Free (~m~) works anywhere
- Focus (~f~) works in any org-mode file
- Navigate (~v~) needs a project (any project.el project)
- Editing (~e~) works with any file (creates matching notes file)

Best experience is within a proper writing project!

** "Do modes save my theme/font permanently?"

*Answer*: No, changes are temporary.

- Modes change theme/font when activated
- Original settings are saved
- Exiting mode restores original settings
- Your actual Emacs configuration is unchanged

This is intentional - modes are temporary environments!

** "Why can't I have Navigate mode AND Distraction-Free at once?"

*Answer*: They conflict in their goals.

- Distraction-Free hides everything → minimal
- Project shows panels → maximal navigation
- These are opposite approaches
- Mutual exclusivity prevents confusion

Choose the right tool for your current task!

** "Can I customize which panels Editing mode shows?"

*Answer*: Currently, the panels are fixed (imenu-list + notes).

But you can:
- Adjust panel widths (percentages)
- Choose different theme
- Change text width
- Use different font

*Future enhancement*: Customizable panel content is planned!

** "What if I don't have treemacs/imenu-list installed?"

*Answer*: Modes gracefully handle missing packages.

- Navigate mode (~v~): Shows warning, some features missing
- Editing mode (~e~): Works but no imenu-list panel
- Distraction-Free/Focus (~m~/~f~): Require writeroom-mode (show error)

Install recommended packages for full experience!

** "Can I create my own custom mode?"

*Answer*: Advanced users can!

Study existing modes in ~modes/org-scribe-modes.el~:
1. Create a minor mode
2. Add an entry to the ~org-scribe-workspace-layouts~ table — this single source of truth automatically derives the exclusivity list (~org-scribe-exclusive-modes~) and wires your new layout into the unified ~org-scribe-workspace~ dispatcher; you no longer need to touch two separate lists/functions by hand
3. Save/restore state appropriately

This is advanced - stick with the four built-in modes initially!

* Troubleshooting

** "Mode activates but looks wrong/broken"

*Check*:
1. Do you have required packages installed?
   - Distraction-Free/Focus need: ~writeroom-mode~
   - Navigate needs: ~treemacs~ and ~imenu-list~
   - Editing needs: ~imenu-list~

2. Are themes installed?
   - ~M-x customize-themes~ to see available
   - Install missing themes via package manager

3. Is your frame wide enough?
   - Editing mode needs ~120+ columns
   - Navigate mode needs ~100+ columns
   - Narrow terminal? Modes may look cramped

** "Exiting mode doesn't restore everything"

*Try*:
1. Activate the mode again: ~F8 F8 X~ (where X is the mode key)
2. Exit properly: ~F8 F8 X~ again
3. If still broken: ~M-x revert-buffer~ or close/reopen file

*Prevention*:
- Always exit modes with the same key that activated them
- Don't kill buffers while mode is active
- Don't force-quit Emacs while in a writing mode

** "Focus mode won't narrow / stays wide"

*Causes*:
1. Cursor not on an org heading
2. Not in org-mode buffer
3. Already at top level (can't narrow to whole file)

*Solution*:
- Position cursor on a scene or chapter heading (*** or **)
- Make sure buffer is in ~org-mode~
- Try from a deeper heading (not the document title)

** "Navigate mode panels are too wide/narrow"

*Solution*:
- Panels size is controlled by the packages themselves
- For imenu-list: ~M-x customize-variable RET imenu-list-size~
- For treemacs: ~M-x customize-variable RET treemacs-width~
- Adjust and restart Navigate mode

** "Editing mode notes file opens in wrong place"

*Expected behavior*:
- The panel shows the project notes file: ~notes/notes.org~, ~notas/notas.org~, or ~notes.org~ for short stories
- The file is found relative to the *project root*, not the manuscript's directory

If opening elsewhere:
- Check that the project root is detected: the ~.org-scribe-project~ marker file should be present
- Check ~org-scribe-editing-right-panel~ - if set to a path string or a function, the panel shows that instead
- If the requested file can't be found, the panel falls back to the project notes file
- Make sure the manuscript is saved to disk (not an unnamed buffer)

** "Themes don't change when mode activates"

*Possible causes*:
1. Theme not installed
2. Consult package not available (uses fallback)
3. Custom theme variable not set

*Solutions*:
#+BEGIN_SRC emacs-lisp
;; Check current theme
(custom-enabled-themes)

;; Manually test theme switching
(load-theme 'poet t)

;; Install consult for smoother theme switching
M-x package-install RET consult RET
#+END_SRC

* Quick Reference

** Mode Activation Keys

| Key | Mode                     | Mnemonic            |
|-----+--------------------------+---------------------|
| ~m~   | Distraction-Free (write) | **M**ode            |
| ~f~   | Focus                    | **F**ocus           |
