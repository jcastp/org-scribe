Implementation roadmap for the recommendations in [[file:fable-plan.org][fable-plan.org]] §6, as
amended by §8 (author's answers) and by [[file:planner-optional.org][planner-optional.org]] (Option C
decision). This document is written for implementing agents/models: each
phase is self-contained, names the exact files and symbols to change, and
ends with acceptance criteria. Execute phases *in order* — later phases
assume earlier deletions have landed.

Author decisions already made (do not re-ask):
- Personal tool; no MELPA constraints, no external users to protect.
- *No backward compatibility required anywhere* — no live projects exist.
  Old file formats, property names, and function names may be dropped
  without migration code. Do not write migration shims.
- Relationships: slim to a simple list; surplus code *deleted outright*.
- Dashboards: keep all until a user trial completes; the cut phase (5) is
  gated on explicit author confirmation.
- Messages: commit to bilingual — add a full Spanish message set (Phase 8).
- Export/manuscript compile: *out of scope* (postponed until a draft nears
  completion). Revision workflow and story chronology: out of scope.
- Planner packaging: stays bundled; per-project gate instead (Phase 4).

* Global rules (apply to every phase)

1. *Test gate.* Before starting a phase, run the full suite and record the
   totals; after the phase, run it again — same pass count minus tests the
   phase legitimately deleted, zero unexpected failures:
   #+begin_src sh
   emacs -batch -l tests/run-all-tests.el -f org-scribe-run-tests-batch
   #+end_src
   Also verify the package still loads cleanly:
   #+begin_src sh
   emacs -Q -l test-load.el
   #+end_src
   Baseline as of 2026-07-29: 508 tests, 1 known unexpected failure
   (bugs-fable.org H11 state leak), 3 skipped. Do not let that number of
   unexpected failures grow.
2. *Docs stay true.* Every phase that changes behavior updates CLAUDE.md
   and README.org in the same commit. CLAUDE.md is loaded by future
   agents; a stale CLAUDE.md sabotages them.
3. *Conventions.* =org-scribe-= public / =org-scribe--= private prefixes;
   never the old =org-scribe/= form. All =defcustom= in
   =core/org-scribe-config.el= with =:group 'org-scribe= (planner
   defcustoms stay in the planner file with =:group 'org-scribe-planner=,
   matching current practice). All new user-facing strings go through
   =(org-scribe-msg 'key …)= with an entry in
   =core/org-scribe-messages.el= — and, after Phase 8 lands, an entry in
   *both* language alists.
4. *One phase = one commit* on the =development= branch (sub-phases 1a/1b/1c
   may be separate commits). Suggested commit messages are given per phase.
5. *Deletion means deletion.* Git history is the archive. Do not leave
   commented-out code, "parked" files, or =-old= copies.
6. *Scope discipline.* If, mid-phase, you find an adjacent bug or an
   appealing refactor, note it at the bottom of this file under
   [[#deferred][Deferred findings]] and finish the phase as specified.

* Phase 4 — Per-project planner gate
:PROPERTIES:
:EFFORT: ~4 h
:RISK: medium
:END:

Decision basis: planner-optional.org §6, Option C (author-approved).
Principle: a project that has not opted in never sees the planner —
no prompts, no mode-line, no health section, no template artifacts.

** 4.1 Marker-file accessors (core)
The gate must be readable *without loading the planner* (hydra and health
need it). Add to =core/org-scribe-core.el=:
- =org-scribe--project-marker-get (root key)= — parse
  =<root>/.org-scribe-project= for a line =# KEY: value= (case-insensitive
  KEY), return the trimmed value string or nil. Reuse/replace the ad-hoc
  parsing the planner already does for =# Plan:= and the Type: parsing in
  core, so there is exactly one marker-file parser afterwards.
- =org-scribe--project-marker-set (root key value)= — idempotently add or
  replace that line, preserving the rest of the file.
- =org-scribe-planner-gate (&optional root)= — returns ='yes=, ='no=, or
  =nil= (undecided) from the =# Planner:= line. Lives in core despite the
  name so callers need no planner load; document that in its docstring.

** 4.2 Gate writers and checks (planner)
In =planning/org-scribe-planner.el= (integration section, lines 2350+):
- =org-scribe-planner--offer-plan-on-create=: on accept → write

  =# Planner: no= and never prompt again for that project.
- =org-scribe-planner--auto-load-plan=: bail out early unless gate is
  ='yes=.
- Mode-line contribution: only when gate is ='yes= (in practice implied by
  a loaded plan, but check explicitly to be robust).
- =org-scribe-plan= dispatcher: in a project with gate ='no=, prompt
  "The planner is disabled for this project. Enable it?" — yes flips the
  marker to =yes= and continues; no exits silently.
- New commands (autoloaded):
  =org-scribe-planner-enable-for-project= /
  =org-scribe-planner-disable-for-project= — toggle the marker line for
  the current project, messaging the result. Add both to
